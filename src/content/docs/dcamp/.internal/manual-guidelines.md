# 매뉴얼 작성 가이드라인

> 이 문서는 내부 작업용입니다. 최종 PDF 출력 시 포함되지 않습니다.

## 작업 방식

1. **초안 작성**: AI가 진행
2. **검토/확정**: 담당자가 진행
3. **커밋/종료**: 담당자가 "끝났다"고 할 때까지 하지 않음

## 작성 원칙

### 1. 실제 시스템 기반 작성
- **추측 금지**: 코드/설정 파일을 확인한 후 매뉴얼 작성
- 카테고리, 필드명, URL 등은 실제 config 파일에서 확인

### 2. 없는 기능은 삭제
- 리비전(버전 관리) - 현재 미사용
- 예약 게시 - 현재 미사용
- SEO 설정 - 현재 미사용
- 다국어/번역 - 현재 미사용
- 미리보기 기능 - 현재 미사용

### 3. 명칭 규칙
- 프로그램명/브랜드명: 영어 소문자 (dcamp, front1, officehour 등)
- 역할명: 영어 소문자 (planning, bizops 등)

### 4. 경로 표기 방식
- 관리자 경로: `메뉴 경로 + URL` 형식
  - 예: `뉴스 관리 → 공지사항 관리 (/admin/dcamp/notice)`
- 작성 절차: Views 페이지에서 버튼 클릭 방식으로 안내
  - 예: `/admin/dcamp/notice` 접속 → "공지사항 작성" 버튼 클릭

### 5. 사용자 화면 연결 명시
- 관리자에서 입력한 내용이 사용자 화면 어디에 표시되는지 명시
- 패싯(필터), 목록, 상세 페이지별 필드 구성 설명

### 6. 불필요한 내용 제거
- 승인 프로세스 관련 내용 삭제
- 과도한 체크리스트/가이드라인 간소화

## 참조 프로젝트

- **dcamp-admin**: 관리자 시스템 (Drupal)
- **dcamp-astro**: 사용자 화면 (Astro)

## 최종 목적

완성된 매뉴얼을 PDF로 출력하여 고객에게 제출
