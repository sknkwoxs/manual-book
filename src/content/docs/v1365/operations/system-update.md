# 시스템 업데이트 실행 가이드

[운영유지 가이드 및 프로세스](./)에서 정의한 범위 01/02/03에 대한 구체적인 실행 절차를 안내합니다.

---

## 01. CMS 코어 및 모듈 보안 업데이트

Omeka Classic 코어와 플러그인의 보안 패치를 적용하는 절차입니다.

### 사전 확인

*   [Omeka Classic Release Notes](https://omeka.org/classic/docs/Release_Notes/) 에서 최신 버전 및 보안 패치 내역 확인
*   현재 운영 서버의 Omeka 버전 확인: `/admin/settings` 하단 또는 `application/config/config.ini`

### 업데이트 절차

1.  **백업**: 업데이트 전 전체 백업 수행 (DB + 파일시스템)
2.  **스테이징 테스트**: 가능한 경우 스테이징 환경에서 먼저 적용
3.  **코어 업데이트**: Omeka Classic 코어 파일 교체 (커스텀 테마 `v1365` 보존 확인)
4.  **DB 마이그레이션**: 업데이트 후 `/admin`에 접속하면 자동 DB 마이그레이션 실행
5.  **플러그인 업데이트**: SolrSearch, ExhibitBuilder, Contribution, SimplePages 등 순차 업데이트
6.  **정상 동작 확인**: 프론트엔드 주요 페이지, 검색, 전시 등 기능 점검

### 주요 플러그인 목록

| 플러그인 | 기능 | 비고 |
| :--- | :--- | :--- |
| **SolrSearch** | Apache Solr 기반 검색 | 색인 재구성 필요 여부 확인 |
| **ExhibitBuilder** | 온라인 전시 구성 | 전시 페이지 정상 렌더링 확인 |
| **Contribution** | 외부 기증/투고 | 기증 양식 정상 동작 확인 |
| **SimplePages** | 정적 페이지 관리 | 메뉴 구조 정상 확인 |

:::danger[주의]
코어 업데이트 시 `/themes/v1365/` 커스텀 테마 파일이 덮어쓰이지 않도록 주의하십시오. 업데이트 전 반드시 테마 디렉토리를 별도 백업합니다.
:::

## 02. 웹사이트 정보 업데이트

기존 페이지 수정, 배너/팝업 제작, 신규 페이지 생성 등의 절차입니다.

### 페이지 텍스트/이미지 수정

1.  `/admin/simple-pages` 접속 → 대상 페이지 선택
2.  WYSIWYG 에디터에서 텍스트 수정 또는 이미지 교체
3.  저장 후 프론트엔드에서 반영 확인

### 메인 이미지/영상 교체

*   메인 페이지 슬라이더 이미지: 테마 파일(`/themes/v1365/`) 내 해당 영역 수정
*   영상 교체: 임베드 코드 또는 파일 경로 변경

### 이벤트 팝업/공지 배너

*   팝업: 테마의 `common/header.php` 또는 별도 팝업 스크립트에서 관리
*   배너: 메인 페이지 또는 공통 영역에 HTML/CSS로 추가

### 신규 단순 페이지 생성

1.  `/admin/simple-pages/add` 접속
2.  제목, URL 슬러그, 본문 작성
3.  상위 페이지(Parent) 지정으로 메뉴 구조 설정
4.  `/admin/appearance/navigation`에서 네비게이션 메뉴에 추가

:::tip[자료 제공 원칙]
텍스트 원고, 이미지, 영상 등은 한국중앙자원봉사센터에서 제공합니다. 수행사는 제공된 자료를 웹사이트에 반영하는 역할을 수행합니다.
:::

## 03. 기능 수정 및 개선

데이터 오류 대응, 버그 수정, 일괄 데이터 입수 등의 절차입니다.

### 데이터 마이그레이션 오류 대응

*   **증상 파악**: 아이템 메타데이터 불일치, 파일 경로 깨짐, 분류체계 오류 등
*   **원인 분석**: DB 직접 조회(`omeka_element_texts`, `omeka_items` 테이블) 또는 어드민 UI로 확인
*   **수정**: 개별 아이템 수정 또는 SQL 일괄 업데이트 (반드시 백업 후 진행)

### 기존 기능 버그 수정

1.  이슈 재현 및 원인 분석
2.  테마(`/themes/v1365/`) 또는 플러그인 코드 수정
3.  수정 후 관련 기능 전체 회귀 테스트

### DB 기록 정보 및 분류체계 수정

*   커스텀 필드(Element ID 237/244/245) 값 정합성 점검
*   컬렉션 구조 재정비 (18개 공동운영기관별 분류 유지)

### 목록 및 파일 일괄 입수 (반기 1회)

1.  **사전 준비**: 엑셀 양식에 맞춰 메타데이터 작성, 파일 규격화
2.  **서버 업로드**: FTP/SFTP를 통해 미디어 파일을 서버 임시 디렉토리에 업로드
3.  **CSV Import**: `/admin/csv-import`에서 CSV 파일 업로드 → Item Type/Collection 지정 → 엘리먼트 매핑 → Import 실행
4.  **Solr 재색인**: `/admin/solr-search` > Index Items 실행 (대량 데이터 처리 시 이용자 적은 시간대 권장)
5.  **결과 검증**: 등록된 아이템 수, 메타데이터, 파일 연결 상태 확인

:::caution[일괄 입수 주의사항]
대량 데이터(약 2만 건) 환경에서 CSV Import와 Solr 재색인은 서버 부하를 유발할 수 있습니다. 야간 또는 이용자가 적은 시간대에 수행하십시오.
:::
