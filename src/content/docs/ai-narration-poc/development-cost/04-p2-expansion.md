## P2 개요

P1에서 구축한 기본 편집 기능을 **다중 사용자 실시간 협업**으로 확장하고, **GPT-4o 대안 파이프라인**을 비교 테스트용으로 구현합니다.

| 항목 | 내용 |
|------|------|
| 우선순위 | **P2 — 확장** |
| 예상 기간 | **4~5주** |
| 핵심 목표 | 실시간 협업 편집 + GPT-4o 비교 테스트 |
| 전제 조건 | P1 완료 (편집 UI, TTS 합성 동작) |

## 모듈별 상세

### 1. 편집 결과 저장부 — 버전 관리 (1주)

| 항목 | 내용 |
|------|------|
| 기간 | 1주 (0.23 M/M) |
| 투입 인력 | 백엔드 개발자 1명 |
| 적용 단가 | 고급 ₩11,500,000/M |

| 이력 추적 | 편집 이력(who/when/what) 기록, 변경 내역 비교(diff) | 중 |
| 롤백 기능 | 특정 버전으로 복원 API | 하 |
| S3 연동 | 버전별 해설 데이터 아카이빙 | 하 |

### 2. 협업 편집부 확장 — CRDT + WebSocket (2주)

| 항목 | 내용 |
|------|------|
| 기간 | 2주 (0.45 M/M) |
| 투입 인력 | 프론트엔드 개발자 1명 + 백엔드 개발자 0.5명 |
| 적용 단가 | 고급 ₩11,500,000/M |

#### 구현 범위

| 기능 | 상세 | 복잡도 |
|------|------|--------|
| Yjs CRDT 통합 | Yjs 라이브러리 기반 충돌 없는 동시 편집 데이터 구조 | 상 |
| WebSocket 서버 | y-websocket 서버 구축, 연결 관리, 인증 | 상 |
| 실시간 커서 | 다중 사용자 커서/선택 영역 실시간 표시 | 중 |
| 사용자 표시 | 현재 편집 중인 사용자 목록, 색상 구분 | 하 |
| 오프라인 지원 | 네트워크 단절 시 로컬 편집, 재연결 시 자동 동기화 | 상 |
| 충돌 해결 | CRDT 기반 자동 충돌 해결, 편집 의도 보존 | 상 |

#### 비용 산출

| 항목 | 산출 근거 | 금액 |
|------|-----------|------|
| 프론트엔드 인건비 | 0.45 M/M × ₩11,500,000 | ₩5,175,000 |
| 백엔드 인건비 | 0.23 M/M × ₩11,500,000 | ₩2,645,000 |
| **소계 (인건비)** | | ₩7,820,000 |
| **예비비 (10%)** | | ₩782,000 |
| **소계** | | **₩8,602,000** |

> **핵심 난이도 요소**: CRDT(Conflict-free Replicated Data Type) 기반 실시간 동시 편집은 기술적 난이도가 높은 모듈입니다. Yjs 라이브러리를 활용하면 구현 부담이 줄지만, 해설 세그먼트의 타임코드 편집과 텍스트 편집을 동시에 CRDT로 관리하는 부분에서 복잡도가 증가합니다.

### 3. GPT-4o 대안 파이프라인 (1~2주)

| 항목 | 내용 |
|------|------|
| 기간 | 1~2주 (0.23~0.45 M/M) |
| 투입 인력 | AI/ML 엔지니어 1명 |
| 적용 단가 | 특급 ₩14,000,000/M |

#### 구현 범위

| 기능 | 상세 | 복잡도 |
|------|------|--------|
| FFmpeg 프레임 추출 | 30초 간격 정지 이미지 추출 파이프라인 | 중 |
| GPT-4o Vision 연동 | 프레임 이미지 기반 장면 분석 API 연동 | 중 |

| 비교 테스트 | Gemini vs GPT-4o 분석 품질/비용/속도 비교 프레임워크 | 중 |
