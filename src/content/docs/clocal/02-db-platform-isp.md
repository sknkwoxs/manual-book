## ISP(정보화 전략 계획)란?

**ISP**는 **Information Strategy Planning**의 약자로, 한국어로는 **정보화 전략 계획** 또는 **정보 시스템 계획**이라고 합니다.

시스템 구축에 앞서 **무엇을, 왜, 어떻게 만들 것인지**를 체계적으로 연구하고 계획하는 과정입니다.

### ISP를 선행하는 이유

| 문제 | ISP 없이 구축 시 | ISP 선행 시 |
|------|-----------------|-------------|
| **요건 불명확** | 구축 중 요건 변경 → 일정/예산 초과 | 사전에 요건 확정 → 안정적 구축 |
| **이해관계자 미합의** | 구축 후 기대와 결과 불일치 | 구축 전 방향 합의 도출 |
| **운영 체계 부재** | 구축 후 운영 주체/예산 미정 | 운영 정책까지 사전 설계 |
| **예산 불확실** | 추가 비용 발생 | 직접/간접 비용 정확히 산출 |

### ISP 연구의 핵심 산출물

- **현황 분석서**: 지금 어떤 상태인가
- **요구사항 정의서**: 무엇이 필요한가
- **시스템 구성안**: 어떻게 만들 것인가
- **예산 산출서**: 얼마나 드는가
- **운영 정책 제안서**: 누가, 어떻게 운영할 것인가

## 1. 사업 개요

| 항목 | 내용 |
|------|------|
| **사업명** | 충남공동체 DB 플랫폼 구축을 위한 ISP 연구 |
| **기간** | 착수일로부터 약 8주 (2개월) |
| **목적** | DB 플랫폼 구축에 앞서 **이해관계자, 업무 협력 구조, 시스템 요건, 예산, 운영 정책**을 종합적으로 연구하여 실현 가능한 구축 계획 수립 |

### 제안 배경

충남지역공동체활성화센터에서는 2025년 충남지역공동체 DB 구축 사전준비를 완료하고, 데이터 수집과 시스템 구축을 동시에 추진하는 계획을 수립하셨습니다.

스컹크웍스스튜디오는 이 계획의 **성공적 실행**을 위해, 시스템 구축에 앞서 **ISP 연구 단계**를 선행할 것을 제안합니다.

| 구분 | 고객사 원안 | SKNK 제안 |
|------|-------------|-----------|
| **접근 방식** | 데이터 수집 + 시스템 구축 동시 진행 | ISP 연구 선행 → 구축 계획 수립 |
| **핵심 산출물** | 플랫폼 + 데이터 | ISP 연구보고서 + 구축 기획안 |
| **리스크** | 구축 중 요건 변경, 예산 초과 | 사전 연구로 리스크 최소화 |
| **장점** | 빠른 착수 | 명확한 방향성, 정확한 예산, 지속 가능한 운영 체계 |

### 왜 ISP 연구가 필요한가?

1. **다양한 이해관계자**: 공동체, 중간지원조직, 행정, 연구기관 등 다층적 참여자 존재
2. **장기 운영 필요**: 일회성 구축이 아닌 지속적 운영 체계 필요
3. **예산 정확성**: 직접 비용(개발)과 간접 비용(운영, 인건비) 모두 사전 산출 필요
4. **충남 지역 특성**: 수도권 대비 이동 거리, 분산된 이해관계자 → 충분한 현장 조사 필요

## 2. 현황 분석 (AS-IS)

### 2.1 데이터 현황

| 항목 | 현황 |
|------|------|
| 수집된 공동체 정보 | 485개+ |
| 저장 형태 | 임시 DB (엑셀/스프레드시트) |
| 분류 체계 | 미정립 |
| 정보 수집 창구 | 외부 설문 (cnhub.kr/survey) |

현재 「2025년 충남지역공동체활성화센터 충남지역 공동체 현황 실태조사」를 통해 공동체의 **현황과 운영 구조, 협력 경험, 지원 수요** 등을 수집하고 있습니다.

### 2.2 해결해야 할 과제

| 과제 | 설명 |
|------|------|
| **이해관계자 정의** | 플랫폼을 누가 사용하고, 누가 관리하며, 누가 정책을 결정하는가? |
| **데이터 표준화** | 다층적 분류 체계, 공동체 프로필 양식 표준화 필요 |
| **운영 체계** | 지속적 데이터 갱신, 품질 관리, 정책 수립 주체 필요 |
| **기술 구현** | 검색/필터/지도, 참여형 등록, 관리자 CMS 등 기능 구현 |
| **예산 계획** | 구축 비용 + 연간 운영 비용 (인건비 포함) 산출 |

## 3. ISP 연구 목표 (TO-BE)

### 3.1 핵심 산출물: ISP 연구보고서

| 항목 | 내용 |
|------|------|
| **이해관계자 분석** | 주요 관계자 맵핑, 역할 정의, 협력 구조 설계 |
| **페르소나 정의** | 플랫폼 이용자 유형별 니즈와 시나리오 정의 |
| **업무 협력 대상** | 협력 기관/부서, 데이터 연계 대상 정의 |
| **시스템 구축 요건** | 기능 요구사항, 기술 검토 사항 도출 |
| **예산 산출** | 직접 비용(개발), 간접 비용(운영/인건비/인프라) 분리 산출 |
| **운영 정책 제안** | 운영팀/정책팀 구성안, 장기 운영 정책 방향 |

### 3.2 기대 효과

1. **명확한 구축 로드맵**: 무엇을, 왜, 얼마에, 누가 운영할지 명확화
2. **예산 정확성**: 구축 후 "예상치 못한 비용" 최소화
3. **지속 가능성**: 일회성 구축이 아닌 장기 운영 체계 설계
4. **이해관계자 합의**: 구축 전 관계자 간 방향 합의 도출

## 4. 주요 수행 과업

### 가. 현황 조사 및 이해관계자 분석 (1~3주)

| 과업 | 내용 |
|------|------|
| **이해관계자 인터뷰** | 센터 실무자, 유관 기관 담당자, 공동체 대표 인터뷰 |
| **현장 조사** | 충남 지역 현장 방문, 업무 환경 파악 |
| **기존 데이터 분석** | 485건 데이터 구조 파악, 품질 점검 |
| **벤치마킹** | 유사 플랫폼 사례 분석 (타 지역 공동체 플랫폼) |

### 나. 요건 분석 및 설계 (4~6주)

| 과업 | 내용 |
|------|------|
| **페르소나 정의** | 이용자 유형별 니즈, 시나리오 정의 |
| **기능 요구사항 도출** | 플랫폼 필수/권장 기능 정의 |
| **데이터 구조 설계** | 분류 체계, 공동체 프로필 양식 설계 |
| **시스템 구성 검토** | 기술 스택, 연동 방안, 인프라 검토 |

### 다. 예산 및 운영 정책 수립 (7~8주)

| 과업 | 내용 |
|------|------|
| **예산 산출** | 직접 비용(개발), 간접 비용(운영/인건비/인프라) 분리 |
| **운영 체계 설계** | 운영팀/정책팀 구성안, 역할 정의 |
| **장기 운영 정책** | 데이터 갱신 정책, 품질 관리, 확장 로드맵 |
| **ISP 연구보고서 작성** | 전체 연구 결과 종합 |

|------|----------|----------|

| 플랫폼 | URL | 주요 특징 |
|--------|-----|----------|
| **경기도마을공동체지원센터** | https://ggmaeul.or.kr | 시군 현황, 센터 활동, 공간대여, 소식지 |
