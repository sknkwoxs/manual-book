# 발표자료 스타일 가이드

> 목적: 이 문서는 좋은생각 CS 시스템 웹 전환 발표자료의 **시각적 기준선**을 정의합니다.  
> 이후 Marp/HTML/PDF/PPTX 작업은 모두 이 문서의 토큰과 규칙을 우선 적용합니다.

---

## 1. 스타일 방향성

### 핵심 원칙
- **장식보다 정보 전달 우선**
- **보고서형 미니멀리즘**
- **고대비, 고가독성**
- **좌정렬 기반의 정돈된 레이아웃**
- **색상은 절제하고 위계는 강하게**

### 목표 인상
- 신뢰감 있는 컨설팅 보고서
- 경영진 보고에 적합한 차분함
- 과하지 않은 브랜드감
- 구조가 정리된 슬라이드

### 참조 기준
사용자 제공 PPTX(`SKNK-2026 한울타리-발표자료.pptx`)에서 확인한 기준:
- 표지: **검정 배경 + 흰 텍스트 중심**
- 폰트: **Noto Sans KR 계열**
- 전체 인상: **블랙/화이트 중심의 미니멀 톤**
- 도형/장식: 최소화

## 2. 디자인 토큰 (Design Tokens)

### 2-1. 메인 컬러 시스템

#### Primary
- **Primary Black**: `#000000`
  - 표지 배경
  - 강한 섹션 구분

- **Primary White**: `#FFFFFF`
  - 표지 텍스트
  - 본문 카드/도형 배경

#### Accent
- **Accent Black**: `#000000`
  - 제목 영역
  - 구분선
  - 강조 박스 좌측선
  - 핵심 위계 요소

#### Neutral
- **Text Primary**: `#111111`
- **Text Secondary**: `#2B2F36`
- **Text Muted**: `#6B7280`
- **Line Default**: `#D9DDE3`
- **Line Soft**: `#ECEFF3`
- **Surface Soft**: `#F7F8FA`
- **Surface Subtle**: `#FAFBFC`

#### Status
- **Warning / Risk**: `#D95C5C`

### 2-2. 색상 사용 원칙
- 한 슬라이드에서 **핵심 색상은 최대 3개**까지만 사용
- **검정/흰색/회색**이 기본 구조를 담당
- 기본 강조는 **블랙(`#000000`)**으로 처리
- 블루는 가능하면 사용하지 않거나, 꼭 필요한 장식 요소에만 제한적으로 사용
- **빨간색은 리스크/경고 외에는 사용 금지**
- 초록/주황/보라 등 추가 컬러는 기본적으로 사용하지 않음

---

## 3. 타이포그래피 시스템

### 3-1. 기본 폰트
- **기본 폰트**: `Noto Sans KR`
- 대체 폰트: `Pretendard`, `맑은 고딕`, `sans-serif`

### 3-2. 폰트 역할 정의

| 역할 | 크기 | 두께 | 색상 | 용도 |
|---|---:|---:|---|---|
| Cover Kicker | 13px | 500 | White 70% | 표지 상단 작은 라벨 |
| Cover Title | 28px | 700 | White | 표지 메인 제목 |
| Cover Subtitle | 20px | 700 | White | 표지 부제 |
| Lead Statement | 22px | 700 | White/Black | 핵심 메시지 |
| Slide Title (H1) | 28px | 700 | Text Primary | 본문 슬라이드 제목 |
| Section Heading (H2) | 20px | 700 | Text Secondary | 블록 내 보조 제목 |
| Sub Heading (H3) | 17px | 700 | Text Primary | 세부 구분 제목 |
| Sub Heading (H4) | 15px | 700 | Text Secondary | 세부 보조 제목 |
| Body Text | 16px | 400~500 | Text Primary | 기본 본문 |
| Table Text | 14px | 400 | Text Primary | 표 내용 |
| Caption / Meta | 12~13px | 400~500 | Text Muted | 보조 설명 |

### 3-3. 타이포 원칙
- 제목은 **굵기와 간격**으로 위계를 만든다
- 강조는 **굵기 또는 색상 중 하나**만 사용한다
- 한국어 본문은 지나치게 작은 폰트를 쓰지 않는다
- 본문은 16px 이하로 내리지 않는다
- 문장 길이는 길어도 **2줄 이내**로 유지하는 것이 이상적

---

## 4. 레이아웃 시스템

### 4-1. 기본 캔버스
- 비율: **16:9**
- 본문 슬라이드 기본 패딩: `0px 56px 52px`
- 타이틀 바 높이: `90px`

### 4-2. 제목 영역 규칙
- 모든 본문 슬라이드 제목은 **검정 타이틀 바** 안에 위치
- 타이틀 바는 슬라이드 상단을 **꽉 채움**
- 제목 아래 첫 본문 블록은 **18~24px 간격**으로 시작

### 4-3. 본문 시작 위치 규칙
- 본문은 항상 제목 라인 아래에서 시작
- 본문 첫 블록의 시작선이 슬라이드마다 달라지지 않도록 유지
- 리스트/문단/표/도식은 공통 간격 규칙을 따른다

### 4-4. 2단 레이아웃 규칙
- 그리드: `1.05fr / 0.95fr`
- 간격: `26px`
- 좌측에는 텍스트, 우측에는 도형/다이어그램 배치 우선

---

## 5. 컴포넌트 시스템

### 5-1. 표지 (Cover)

#### 규칙
- 배경: `#000000`
- 텍스트: `#FFFFFF`
- **스컹크웍스스튜디오 로고 필수**
- 우측 상단에 **사업명 표기 필수**
- 작은 Kicker → 메인 제목 → 부제 → 구분선 → 핵심 메시지 → 메타 순서
- 로고는 밝게 보정해 검정 배경에서 식별되도록 처리

#### 금지 사항
- 과한 그라데이션
- 불필요한 도형/아이콘
- 여러 색상 혼합

### 5-1-1. 스컹크웍스스튜디오 시그니처 요소

- 검은 타이틀 영역 안에서만 사용
- 원칙: **장식은 1종만** 사용
- 권장 형태:
  - 우측 상단의 얇은 흰색/회색 스트립
  - 또는 짧은 분절형 화이트/그레이 바
- 목적: 브랜드감 부여, 과한 장식 금지

---

### 5-2. 제목 라인 (Title Line)

#### 규칙
- 모든 본문 슬라이드의 `h1`은 **검은 배경의 타이틀 바** 안에 위치
- 제목 텍스트는 **화이트** 사용
- 우측 상단에는 **사업명**을 작게 고정 표기
- 제목 바는 슬라이드 상단 전체 폭을 사용
- 제목 아래 첫 본문 블록은 **18px 간격**으로 시작

#### 목적
- 슬라이드 간 시각적 리듬 통일
- 제목만 봐도 같은 템플릿임이 느껴지도록 함

---

### 5-3. 카드 (Card)

#### 스타일
- 배경: `#FFFFFF`
- 테두리: `1px solid #D9DDE3`
- 라운드: `10px`
- 그림자: 사용하지 않음
- 패딩: `18px 18px 16px`
- 최소 높이: `156px`
- 카드 상단 4px 블랙 바 고정

#### 용도
- Executive Summary
- 포인트 요약
- 비교/옵션 설명

---

### 5-4. Decision Box

#### 스타일
- 배경: `#FFFFFF`
- 테두리: `1px solid #D9DDE3`
- 좌측 강조선: `6px solid #000000`
- 라운드: `12px`
- 패딩: `16px 18px`

#### 용도
- 의사결정 요청
- 핵심 결론 강조

---

### 5-5. Chip

#### 스타일
- 배경: `#F5F7FA`
- 테두리: `1px solid #E2E8F0`
- 텍스트: `#2F3945`
- 라운드: pill 형태
- 크기: 12px / bold

#### 용도
- 키워드 강조
- 우선순위 태그
- 요구사항 묶음 표시

---

### 5-6. Blockquote / Insight Box

#### 스타일
- 좌측 블랙 강조선: `4px solid #000000`
- 배경: `#FAFBFC`
- 텍스트: 기본 본문색
- 라운드: 오른쪽만 약하게 적용

#### 용도
- 핵심 메시지
- 인사이트 문장
- 장표 시작 요약

---

### 5-7. Diagram Box

#### 스타일
- 배경: `#FFFFFF`
- 테두리: `1px solid #D9DDE3`
- 라운드: `12px`
- 패딩: `14px`
- 그림자: 없음

#### 내부 규칙
- SVG 이미지 자체도 동일 톤의 border를 유지
- 하단에는 12px muted caption 배치

#### 목적
- 도형 스타일을 텍스트 카드와 동일 체계로 맞춤
- 도식이 슬라이드 안에서 튀지 않게 함

### 5-7-1. 그래프 / 표 패널

#### 스타일
- 외곽: `1px solid #D9DDE3`
- 배경: `#FFFFFF`
- 라운드: `12px`
- 상단 헤더 바: `#000000`
- 헤더 텍스트: `#FFFFFF`
- 본문: 흰 배경 위 검은 텍스트

#### 목적
- 표와 그래프에도 같은 시각 시스템 적용
- 정보성 데이터가 “일반 본문”처럼 흩어지지 않도록 함

---

### 5-8. 목차 (TOC)

#### 규칙
- 표지 다음 1장으로 고정
- 2열 그리드 배치 사용
- 각 항목은 **번호형 배지 + 텍스트** 조합
- 배지 크기 30px, 텍스트 16px
- 번호 배지는 검정 배경 / 흰 텍스트 사용

#### 목적
- 발표 흐름을 빠르게 인지하게 함
- 구조적 안정감 제공

---

### 5-9. 페이지 번호

#### 규칙
- 하단 중앙 정렬 고정
- 크기: 12px 내외
- 색상: `#9AA3AD`
- 표지에는 페이지 번호 표시하지 않음

#### 목적
- PPT/PDF/HTML 결과물 모두에서 공통 위치 확보
- 발표 중 페이지 참조가 쉬워지도록 함

---

## 6. 표(Table) 스타일 가이드

### 6-1. 기본 스타일
- 테이블 폭: `100%`
- 글자 크기: `14px`
- 헤더 배경: `#F7F8FA`
- 헤더 텍스트: `#111111`
- 헤더 하단선: `1px solid #D9DDE3`
- 본문 행 하단선: `1px solid #ECEFF3`
- 셀 패딩: `10px 12px`

### 6-2. 표 디자인 원칙
- 줄무늬 배경 사용 금지
- 과도한 테두리 박스 사용 금지
- 수치 열은 우측 정렬 가능
- 텍스트는 가급적 2줄 이내 유지
- “예쁘게”보다 “읽기 쉽게”를 우선

### 6-3. 표의 역할
- 메뉴 수량 요약
- 우선순위 비교
- 기능 범위 정리
- 단계별 계획 요약

---

## 7. 도식 / 다이어그램 스타일 가이드

### 7-1. 공통 규칙
- 선 두께, 도형 라운드, 캡션 스타일을 모두 동일하게 유지
- 색상은 **블랙 + 화이트 + 회색** 중심으로 제한
- 경고/병목만 빨간색 사용

### 7-2. Mermaid / SVG 규칙
- 다이어그램은 흰 배경으로 export
- 박스 라운드와 텍스트 크기를 deck 스타일에 맞춘다
- 복잡한 다이어그램은 한 단계 단순화해서 넣는다
- 도식 하나에 요소를 과도하게 넣지 않는다

### 7-3. 캡션 규칙
- 위치: 도식 하단
- 크기: 12px
- 색상: `#6B7280`
- 문장 길이: 1줄 중심

## 9. 슬라이드별 적용 우선순위

### 표지
- 블랙 배경
- 화이트 타이포
- 스컹크웍스스튜디오 로고 필수
- 우측 상단 사업명 필수
- 얇은 시그니처 장식 1종 허용

### 목차
- 표지 바로 다음 장
- 번호 배지 + 항목 텍스트 구조
- 다른 슬라이드보다 구조적으로 단순해야 함

### 본문 슬라이드
- 흰 배경
- 동일 검은 타이틀 바
- 동일 본문 시작 위치

### 요약 슬라이드
- 카드형 박스 사용 가능
- 카드도 동일 토큰 적용

### 도식 슬라이드
- 텍스트와 도식의 시작선 정렬
- diagram-wrap 필수

### Decision Slide
- Decision Box를 주인공으로 배치
- 강조색은 블랙을 기본으로 사용

## 10. 실제 적용 체크리스트

- 메인 컬러가 검정/흰색/파랑 중심으로 정리되었는가?
- 표지에 스컹크웍스스튜디오 로고가 들어갔는가?
- 우측 상단 사업명이 일관되게 보이는가?
- 목차가 표지 다음에 들어가는가?
- 제목 영역이 블랙이고 제목이 화이트인가?
- 제목 라인이 모든 본문 슬라이드에서 같은 위치와 길이로 보이는가?
- 본문이 제목 아래 같은 높이에서 시작하는가?
- 표 스타일이 모든 슬라이드에서 동일한가?
- 도형/다이어그램 박스 스타일이 카드와 같은 체계를 따르는가?
- 그래프/표 패널도 동일 체계를 따르는가?
- 페이지 번호가 하단 중앙에 있는가?
- 폰트 크기가 장표마다 들쭉날쭉하지 않은가?
- 빨간색이 필요한 곳에만 쓰였는가?
