# Google Slides 도형 배치 가이드

> 목적: 기존 Mermaid 초안을 **Google Slides 도형으로 다시 그릴 수 있도록** 슬라이드별 배치 규칙을 정리합니다.

---

## 공통 배치 원칙

### 1. 기본 캔버스 규칙
- 슬라이드 비율: 16:9
- 좌우 여백: 각 40px 이상
- 상단 제목 영역: 전체 높이의 약 15%
- 본문/도식 영역: 전체 높이의 약 70%
- 하단 캡션/출처 영역: 전체 높이의 약 10%

### 2. 도형 규칙
- **직사각형**: 시스템/기능 박스
- **둥근 직사각형**: 사용자/화면/경험 요소
- **원통형 또는 원통 느낌 아이콘**: DB/데이터 저장소
- **점선 테두리 박스**: 외부 시스템/별도 단계/예외 영역
- **실선 화살표**: 정상 흐름
- **점선 화살표**: 수작업/임시 흐름/수동 재가공

### 3. 텍스트 규칙
- 박스 안 텍스트는 2줄 이내
- 화살표 라벨은 1~2단어만 사용 (`엑셀`, `수동`, `API`, `업로드`)
- 한 도식 안에서 색상 의미는 최대 3개만 사용

---

## 슬라이드 4용: 현행 시스템 연결도

### 목적
현행이 “통합 시스템”이 아니라 “분산 시스템 + 수동 연결 구조”임을 한눈에 보여줌

### 레이아웃
- 중앙 좌측: `CS 시스템`
- 중앙 우측 상단: `홈페이지/어드민`
- 중앙 우측 중단: `CMS`
- 하단 좌측: `외부몰 / Playauto`
- 하단 우측: `WEHAGO / 정산`

### 연결 방식
- `CS 시스템 ↔ 홈페이지/어드민`: 점선 화살표, 라벨 `엑셀`
- `CS 시스템 ↔ CMS`: 점선 화살표, 라벨 `수동`
- `외부몰 → CS 시스템`: 점선 화살표, 라벨 `다운로드`
- `홈페이지/어드민 → WEHAGO`: 점선 화살표, 라벨 `재가공`

### 강조 요소
- 도식 하단 빨간 캡션 박스:
  `직접 연동보다 사람이 시스템 사이를 연결하는 구조`

## 슬라이드 5용: 부서 인터뷰 종합도

### 목적
부서별 의견이 결국 동일한 문제군으로 수렴된다는 점을 시각화

### 레이아웃
- 상단 좌우로 5개 작은 박스 배치
  - 정기구독팀
  - 경영지원팀
  - 편집팀
  - 외주 콜센터
  - 영업추진팀
- 중앙 큰 원 또는 둥근 직사각형: `공통 문제 도출`
- 하단 4개 작은 박스:
  - 엑셀 수작업
  - 중복 입력
  - 검색/조회 불편
  - 권한/연계 한계

### 연결 방식
- 각 부서 박스 → 중앙 허브
- 중앙 허브 → 하단 문제군 4개

### 디자인 팁
- 상단 부서는 회색/밝은 파랑
- 중앙 허브는 진한 파랑
- 하단 문제군은 연한 빨강 계열

---

## 슬라이드 7용: 핵심 병목 프로세스

### 목적
병목이 어느 한 화면이 아니라 프로세스 전체에 걸쳐 있음을 보여줌

### 레이아웃
좌에서 우로 가는 5단 구조:
1. 주문 수집
2. 엑셀 가공
3. CS 시스템 등록
4. 조회/상담/수정
5. 정산/후속처리

### 강조 방법
- 2, 3, 5번 박스에 빨간 테두리 또는 옅은 빨강 배경
- 각 박스 아래 작은 회색 캡션 추가 가능
  - 주문 수집: `채널별 분산`
  - 엑셀 가공: `수동 표준화`
  - CS 시스템 등록: `일괄 업로드 부담`
  - 정산/후속처리: `별도 추출/재가공`

### 디자인 팁
- 화살표는 굵은 실선
- 병목 구간만 붉은색 강조 원 또는 배지 표시

---

## 슬라이드 8용: 웹 전환 개념도

### 목적
웹 전환이 왜 핵심 전제조건인지를 단순하게 설명

### 레이아웃
- 좌측 큰 박스: `로컬 C/S 프로그램`
- 우측 큰 박스: `웹 기반 CS 시스템`
- 우측 박스 아래 4개 작은 수직 박스:
  - 권한관리 강화
  - API 연계 확장
  - 유지보수 단순화
  - 브라우저 접근

### 디자인 팁
- 좌측은 회색 계열, 우측은 파랑 계열
- 좌→우 큰 화살표 사용
- 화살표 위 문구: `웹 전환`

---

## 슬라이드 9용: 템플릿 기능 개념도

### 목적
하나의 CS 데이터가 여러 외부 양식으로 분기되는 모습을 보여줌

### 레이아웃
- 상단 중앙: `CS 시스템 데이터`
- 중간: `템플릿 선택 / 컬럼 매핑`
- 하단 4분기:
  - 외부몰 업로드 양식
  - 물류 업로드 양식
  - 정산/ERP 양식
  - 콜센터/리포트 양식

### 디자인 팁
- 상단 박스는 진한 파랑
- 중간 박스는 중간 톤 파랑
- 하단 4개는 같은 크기의 흰색 박스 + 연한 파란 테두리
- 하단 각 박스에 작은 아이콘 넣으면 이해도 상승

---

## 슬라이드 10용: 단계적 개발 전략

### 목적
왜 단계적 접근이 필요한지 명확히 보여줌

### 레이아웃
- 좌측 큰 박스: `1단계 / CS 시스템 우선 구축`
- 우측 큰 박스: `2단계 / 어드민 & CMS 고도화`
- 좌측 박스 하단 작은 설명:
  `회원/구독/상담/정산 병목 해소`
- 우측 박스 하단 작은 설명:
  `편집/콘텐츠/웹 운영 개선`

### 강조 요소
- 1단계 박스를 더 크게, 더 진하게 표시
- 2단계는 회색 또는 연한 파랑으로 표시
- 두 박스 사이 굵은 화살표 사용

---

## 슬라이드 11용: 메뉴 분석 차트

### 목적
메뉴 과다와 재구성 필요성을 수치로 설득

### 추천 형식
Google Slides 기본 차트보다 **가로 막대형**이 더 읽기 쉬움

### 권장 표시 방식
- 전체 메뉴 109개
- 존치 42개
- 통합 7개
- 폐기 후보 58개
- 미확정 2개

### 레이아웃
- 좌측: 가로 막대 또는 도넛 차트
- 우측: 핵심 인사이트 3개
  - 절반 이상이 폐기 후보
  - 실제 핵심 사용 메뉴는 제한적
  - 메뉴 재구성은 기능 축소가 아니라 흐름 개선

---

## 슬라이드 13용: 고객 360도 UX 와이어프레임

### 목적
‘한 화면에서 끝나는 업무’라는 UX 방향을 설명

### 레이아웃
- 좌측 30%: 고객 검색/리스트 영역
- 우측 70%: 고객 상세 영역

### 상세 배치
- 우측 상단: 고객명, 연락처, 상태 배지
- 우측 중단 탭 5개:
  - 기본정보
  - 구독
  - 결제
  - 발송
  - 상담이력
- 우측 상단 버튼:
  - 구독변경
  - 상담등록
  - 송장확인
  - 템플릿추출

### 도형 사용 팁
- 탭은 얇은 직사각형 5개
- 현재 활성 탭만 파란색 배경
- 상세 영역은 흰색 큰 박스 안에 2열 정보 정렬

---

## 슬라이드 14용: 단계별 타임라인

### 목적
실행 방향을 한 장으로 요약

### 레이아웃
- 좌→우 타임라인 2단 구조
- 1단계: CS 시스템 웹 전환
- 2단계: 어드민/CMS 고도화

### 각 단계 아래 표시할 문구
#### 1단계
- 핵심 병목 해소
- 기능요건/UX 정리
- RFP 및 이행계획 구체화

#### 2단계
- 콘텐츠 운영 개선
- 웹 운영 기능 고도화
- 필요한 범위 내 연계 강화

### 디자인 팁
- 1단계는 진한 파랑, 2단계는 회색+파랑 포인트
- 타임라인 아래에 얇은 회색 선 추가

---

## 마지막 체크리스트

- 한 도식에 박스는 7개 이하 유지
- 한 박스 안 텍스트는 2줄 이하 유지
- 빨간색은 문제/병목에만 사용
- 파란색은 해결방안/권고안에만 사용
- 보라/초록/주황 등 추가 색상은 최소화
