# 자동화 프로세스 (BPR)

[주문수집 → 자동입력 → CMS권한부여 → 배송]의 One-Stop 자동화 흐름 설계

---

## 프로세스 재설계 개요

### AS-IS vs TO-BE

| 구분 | AS-IS (수작업) | TO-BE (자동화) |
|------|---------------|----------------|
| 주문 수집 | 각 채널 수동 접속/다운로드 | API 자동 수집 |
| 데이터 입력 | Excel → CS 수동 입력 | 자동 연동/입력 |
| 권한 부여 | CMS 별도 접속, 수동 처리 | 결제 완료 시 자동 부여 |
| 배송 처리 | 수동 연동 | 자동 연동 (택배사 API) |
| 알림 | 없음 또는 수동 | 자동 알림 (이메일/SMS) |

---

## TO-BE 프로세스 흐름

### 1. 전체 자동화 흐름

```
┌─────────────────────────────────────────────────────────────────┐
│                    TO-BE: One-Stop 자동화 프로세스               │
└─────────────────────────────────────────────────────────────────┘

[주문 발생]
    │
    ▼
┌─────────────┐
│ 1. 자동 수집 │ ◀── 자사몰 API / 외부몰 API / Webhook
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 2. 자동 입력 │ ◀── 데이터 정규화 → 통합 DB 저장
└──────┬──────┘
       │
       ▼
┌─────────────┐     ┌─────────────┐
│ 3. 결제 확인│────▶│ 자동 권한   │ ◀── CMS API 연동
│    (PG연동) │     │    부여     │
└──────┬──────┘     └─────────────┘
       │
       ▼
┌─────────────┐     ┌─────────────┐
│ 4. 배송 연동│────▶│ 송장 등록   │ ◀── 택배사 API
└──────┬──────┘     │ 배송 추적   │
       │           └─────────────┘
       ▼
┌─────────────┐
│ 5. 알림 발송│ ◀── 결제완료, 권한부여, 배송시작, 배송완료
└─────────────┘
```

## 자동화 포인트

### 트리거 기반 자동화

| 트리거 이벤트 | 자동 실행 액션 |
|--------------|---------------|
| 주문 생성 | 고객 매칭, 주문 등록 |
| 결제 완료 | 구독 생성, CMS 권한 부여 |
| 구독 만료 D-7 | 갱신 안내 알림 |
| 구독 만료 | CMS 권한 해제 |
| 배송 출고 | 송장 등록, 알림 발송 |
| 배송 완료 | 상태 업데이트, 알림 |

### 스케줄 기반 자동화

| 주기 | 작업 | 설명 |
|------|------|------|
| 5분 | 외부몰 주문 수집 | API 폴링 |
| 1시간 | 배송 상태 업데이트 | 택배사 API 조회 |
| 매일 00:00 | 구독 만료 처리 | 권한 해제 |
| 매일 09:00 | 만료 예정 알림 | D-7, D-3, D-1 |

## 성과 지표 (KPI)

| 지표 | AS-IS | TO-BE 목표 |
|------|-------|-----------|
| 주문→권한부여 시간 | __시간 | 5분 이내 |
| 수작업 시간/일 | __시간 | 30분 이내 |
| 데이터 오류율 | __% | 0.1% 이하 |
| 자동화율 | 0% | 90% 이상 |
