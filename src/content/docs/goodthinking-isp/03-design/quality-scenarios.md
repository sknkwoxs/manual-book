# 품질 속성 시나리오

좋은생각 C/S → Web 전환 프로젝트에서 달성해야 할 품질 속성별 구체적인 시나리오를 정의합니다.

---

## 품질 속성 시나리오 구조

각 시나리오는 다음 6가지 요소로 구성됩니다:

| 요소 | 설명 |
|------|------|
| **Source (자극원)** | 시나리오를 유발하는 주체 |
| **Stimulus (자극)** | 시스템에 도착하는 이벤트/요청 |
| **Artifact (대상)** | 자극을 받는 시스템 구성요소 |
| **Environment (환경)** | 자극이 발생하는 상황/조건 |
| **Response (응답)** | 시스템이 자극에 대해 취하는 행동 |
| **Response Measure (응답 측정)** | 응답의 측정 가능한 품질 기준 |

---

## 1. 가용성 (Availability) 시나리오

### A-1: 웹 서버 장애 대응

| 요소 | 내용 |
|------|------|
| **Source** | 내부 - 웹 서버 |
| **Stimulus** | 서버 프로세스 크래시 |
| **Artifact** | 웹 관리자 시스템 |
| **Environment** | 정상 운영 시간 (09:00~18:00) |
| **Response** | 자동 페일오버 및 서비스 복구 |
| **Response Measure** | 서비스 중단 시간 5분 이내, 연간 가용률 99.5% |

### A-2: 외부 채널 연동 장애

| 요소 | 내용 |
|------|------|
| **Source** | 외부 - 네이버 스마트스토어 API |
| **Stimulus** | API 타임아웃 또는 오류 응답 |
| **Artifact** | 주문 수집 모듈 |
| **Environment** | 자동 주문 수집 배치 실행 중 |
| **Response** | 재시도 후 실패 시 수동 처리 대기열 등록 및 알림 |
| **Response Measure** | 3회 재시도, 담당자 알림 1분 이내 |

### A-3: 데이터베이스 장애

| 요소 | 내용 |
|------|------|
| **Source** | 내부 - 통합 DB 서버 |
| **Stimulus** | DB 연결 실패 |
| **Artifact** | 전체 시스템 |
| **Environment** | 정상 운영 중 |
| **Response** | 읽기 전용 레플리카로 자동 전환, 쓰기 작업 큐잉 |
| **Response Measure** | 읽기 서비스 30초 이내 복구, 데이터 유실 0건 |

---

## 2. 성능 (Performance) 시나리오

### P-1: 주문 데이터 일괄 수집

| 요소 | 내용 |
|------|------|
| **Source** | 시스템 - 스케줄러 |
| **Stimulus** | 일일 주문 수집 배치 실행 (약 500건/일) |
| **Artifact** | 주문 수집 배치 모듈 |
| **Environment** | 피크 시간대 (10:00, 14:00) |
| **Response** | 모든 채널 주문 수집 완료 |
| **Response Measure** | 10분 이내 완료, 오류율 0.1% 미만 |

### P-2: 고객 조회 응답

| 요소 | 내용 |
|------|------|
| **Source** | CS 담당자 |
| **Stimulus** | 고객 정보 검색 (이름, 전화번호, 주문번호) |
| **Artifact** | 고객 조회 화면 |
| **Environment** | 동시 사용자 10명 |
| **Response** | 통합된 고객 정보 및 거래 이력 표시 |
| **Response Measure** | 응답 시간 2초 이내, 검색 결과 정확도 100% |

### P-3: 대량 데이터 마이그레이션

| 요소 | 내용 |
|------|------|
| **Source** | 시스템 관리자 |
| **Stimulus** | 레거시 데이터 마이그레이션 실행 (약 50만 건) |
| **Artifact** | 데이터 마이그레이션 모듈 |
| **Environment** | 비운영 시간 (야간) |
| **Response** | 데이터 검증 후 통합 DB 적재 |
| **Response Measure** | 4시간 이내 완료, 데이터 정합성 100% |

---

## 3. 보안 (Security) 시나리오

### S-1: 개인정보 접근 통제

| 요소 | 내용 |
|------|------|
| **Source** | 내부 사용자 (CS 담당자) |
| **Stimulus** | 고객 개인정보 조회 요청 |
| **Artifact** | 고객 정보 API |
| **Environment** | 정상 운영 중 |
| **Response** | 권한 검증 후 마스킹 처리된 정보 제공 |
| **Response Measure** | 무권한 접근 차단 100%, 감사 로그 기록 100% |

### S-2: 외부 침입 시도

| 요소 | 내용 |
|------|------|
| **Source** | 외부 - 악의적 사용자 |
| **Stimulus** | SQL Injection, XSS 공격 시도 |
| **Artifact** | 웹 애플리케이션 |
| **Environment** | 정상 운영 중 |
| **Response** | 공격 탐지, 차단, 관리자 알림 |
| **Response Measure** | 공격 차단 100%, 알림 발송 1분 이내 |

### S-3: 민감 데이터 유출 방지

| 요소 | 내용 |
|------|------|
| **Source** | 내부 사용자 |
| **Stimulus** | 대량 고객 데이터 다운로드 시도 |
| **Artifact** | 데이터 내보내기 기능 |
| **Environment** | 정상 운영 중 |
| **Response** | 승인 프로세스 실행, 다운로드 기록 |
| **Response Measure** | 100건 초과 시 승인 필요, 모든 다운로드 로깅 |

---

## 4. 변경용이성 (Modifiability) 시나리오

### M-1: 신규 판매 채널 추가

| 요소 | 내용 |
|------|------|
| **Source** | 개발팀 |
| **Stimulus** | 새로운 판매 채널 (예: 11번가) 연동 요청 |
| **Artifact** | 주문 수집 모듈 |
| **Environment** | 설계 시점 |
| **Response** | 신규 채널 어댑터 개발 및 배포 |
| **Response Measure** | 개발 공수 5일 이내, 기존 코드 수정 최소화 |

### M-2: 업무 프로세스 변경

| 요소 | 내용 |
|------|------|
| **Source** | 운영팀 |
| **Stimulus** | 배송 프로세스 단계 추가 요청 |
| **Artifact** | 워크플로우 엔진 |
| **Environment** | 설계 시점 |
| **Response** | 워크플로우 설정 변경으로 대응 |
| **Response Measure** | 코드 수정 없이 설정만으로 변경, 반영 시간 1일 이내 |

### M-3: 리포트 양식 변경

| 요소 | 내용 |
|------|------|
| **Source** | 경영팀 |
| **Stimulus** | 월간 리포트 항목 추가 요청 |
| **Artifact** | 리포트 생성 모듈 |
| **Environment** | 운영 시점 |
| **Response** | 리포트 템플릿 수정 및 적용 |
| **Response Measure** | 개발 공수 2일 이내 |

---

## 5. 사용성 (Usability) 시나리오

### U-1: 신규 직원 시스템 학습

| 요소 | 내용 |
|------|------|
| **Source** | 신규 CS 담당자 |
| **Stimulus** | 첫 시스템 사용 |
| **Artifact** | 웹 관리자 UI |
| **Environment** | 교육 세션 |
| **Response** | 기본 업무 수행 가능 |
| **Response Measure** | 4시간 교육 후 독립 업무 수행 가능 |

### U-2: 오류 발생 시 안내

| 요소 | 내용 |
|------|------|
| **Source** | 일반 사용자 |
| **Stimulus** | 잘못된 입력 또는 시스템 오류 |
| **Artifact** | 웹 UI |
| **Environment** | 정상 운영 중 |
| **Response** | 명확한 오류 메시지 및 해결 방법 제시 |
| **Response Measure** | 사용자가 1회 안내로 문제 해결 가능 |

### U-3: 자주 사용하는 기능 접근성

| 요소 | 내용 |
|------|------|
| **Source** | CS 담당자 |
| **Stimulus** | 고객 조회 → 상담 이력 등록 → 주문 처리 |
| **Artifact** | 웹 관리자 UI |
| **Environment** | 전화 상담 중 |
| **Response** | 최소 클릭으로 업무 흐름 완료 |
| **Response Measure** | 주요 업무 흐름 5클릭 이내 완료 |

---

## 6. 운영성 (Operability) 시나리오

### O-1: 시스템 모니터링

| 요소 | 내용 |
|------|------|
| **Source** | 시스템 관리자 |
| **Stimulus** | 시스템 상태 점검 |
| **Artifact** | 모니터링 대시보드 |
| **Environment** | 정상 운영 중 |
| **Response** | 실시간 시스템 상태 및 알림 표시 |
| **Response Measure** | 이상 징후 5분 이내 감지, 알림 발송 |

### O-2: 배치 작업 실패 처리

| 요소 | 내용 |
|------|------|
| **Source** | 시스템 - 배치 스케줄러 |
| **Stimulus** | 배치 작업 실패 |
| **Artifact** | 배치 모니터링 시스템 |
| **Environment** | 자동 배치 실행 중 |
| **Response** | 실패 알림, 수동 재실행 가능 |
| **Response Measure** | 실패 알림 즉시 발송, 재실행 UI 제공 |

| 3 | A-2: 외부 채널 연동 장애 | 가용성 | 높음 |
