구독 관리는 서비스의 근간이 되는 정기구독의 등록, 변경, 해지 등 전체 생애주기를 관리하는 모듈입니다. 현재 C/S 시스템과 홈페이지 어드민, 그리고 웹진(CMS) 사이의 데이터가 수동으로 복사되어 처리되는 병목 현상을 해결하는 데 초점을 맞춥니다. 구독 상태 변화에 따른 자동 권한 제어와 효율적인 만료 관리를 통해 정기구독팀의 업무 공수를 획기적으로 줄이고 고객 서비스를 자동화합니다.

### SB-01: 구독 등록/해지/변경

| 항목 | 내용 |
|------|------|
| **번호** | SB-01 |
| **제목** | 구독 등록/해지/변경 |
| **목표** | 구독 정보의 신규 등록, 중간 해지, 옵션 변경 등의 기본 기능을 하나의 인터페이스에서 처리할 수 있게 합니다. |
| **배경** | 내부 관리자 입력분과 홈페이지 신청 데이터를 단일 DB에서 관리하여 정합성을 유지하고 복잡한 변경 요청에 신속히 대응합니다. 현재 C/S와 웹(PTM_Regular_Orders) 데이터가 별도로 관리되고 있습니다. |
| **우선순위** | 필수 |
| **현행지원 여부** | C/S 지원 (PT_Subscribe, sp_PT_SubscribeCancel). 웹에서는 PTM_Regular_Orders 별도 |

### SB-02: 수신자 관리 (배송 주소 분리)

| 항목 | 내용 |
|------|------|
| **번호** | SB-02 |
| **제목** | 수신자 관리 (배송 주소 분리) |
| **목표** | 결제자와 도서를 실제로 받는 수신자를 명확히 분리하여 1:N 관계의 배송처 관리를 지원합니다. |
| **배경** | 선물이나 단체 구독 시 각기 다른 주소지로 정확한 발송이 가능하도록 체계적인 배송 정보를 유지하여 배송 사고를 방지합니다. 기존 C/S의 고객 ≠ 수신자 분리 구조(PT_Receiver)를 계승합니다. |
| **우선순위** | 필수 |
| **현행지원 여부** | C/S 지원 (PT_Receiver 43 cols). 고객 ≠ 수신자 분리 구조 |

### SB-03: 구독 기간 자동 계산

| 항목 | 내용 |
|------|------|
| **번호** | SB-03 |
| **제목** | 구독 기간 자동 계산 |
| **목표** | 구독 시작일과 상품 개월 수를 바탕으로 종료일을 자동으로 산출하는 정밀한 계산 로직을 내장합니다. |
| **배경** | 휴간이나 연장 등 특수 상황을 반영한 자동 갱신으로 수기 계산 오류를 차단하고 데이터 신뢰도를 높입니다. 현재 C/S에서 Function(fn_PT_GetEndDate 등) 기반으로 자동 계산을 지원하고 있습니다. |
| **우선순위** | 필수 |
| **현행지원 여부** | C/S 지원 (fn_PT_GetEndDate, fn_PT_GetSubsCnt). Function 기반 자동 계산 |

### SB-04: 만료 예정 알림

| 항목 | 내용 |
|------|------|
| **번호** | SB-04 |
| **제목** | 만료 예정 알림 |
| **목표** | 구독 종료 예정 고객을 사전에 식별하여 자동으로 알림을 발송하고 갱신 안내 환경을 구축합니다. |
| **배경** | 수동 조회와 개별 연락에 의존하던 갱신 업무를 자동화하여 구독 이탈률을 낮추고 담당자가 핵심 관리에 집중할 수 있게 합니다. 현재는 만료 확인을 수동으로 조회합니다. (자동 갱신은 나이스페이 PG 정기결제 API를 현재 사용하고 있지 않아 불가 — 2차 검토 대상) |
| **우선순위** | 높음 |
| **현행지원 여부** | 미지원. 만료 확인은 수동 조회 |

### SB-05: 외부 시스템 열람 권한 자동 연동

| 항목 | 내용 |
|------|------|
| **번호** | SB-05 |
| **제목** | 외부 시스템 열람 권한 자동 연동 |
| **목표** | 구독 상태 변화가 웹진이나 외부 콘텐츠 서비스 이용 권한과 연동되도록 Excel 기반 일괄 처리 또는 내부 DB 직접 연동을 구축합니다. 현행 업무에서 외부 시스템 간 API를 사용하지 않으므로 Excel 템플릿 기반으로 처리합니다. |
| **배경** | 현재 수동으로 아이디와 구독 여부를 복사하여 붙여넣는 비효율적인 수작업 병목을 근본적으로 해소하고 서비스 품질을 향상합니다. CS(PT_Subscribe)에서 CMS(ptcms_member)로의 수동 처리가 핵심 병목으로 확인되었습니다 (편집팀 인터뷰). |
| **우선순위** | 필수 |
| **현행지원 여부** | **미지원 — 핵심 병목**. CS(PT_Subscribe) → CMS(ptcms_member) 수동 처리. 편집팀 인터뷰에서 어드민→CMS 수동 복사·붙여넣기 확인 — 병목 ⑰과 연계 |

### SB-06: 선물 선발송 프로세스 단순화

| 항목 | 내용 |
|------|------|
| **번호** | SB-06 |
| **유형** | 신규 요건 (인터뷰 도출) |
| **제목** | 선물 선발송 프로세스 단순화 |
| **목표** | 구독 사은품이나 선물을 구독 생성과 동시에 먼저 발송해야 하는 업무 단계를 대폭 간소화합니다. |
| **배경** | 복잡한 우회 프로세스를 원클릭 선발송 기능으로 개선하여 상담 공수를 줄이고 고객 만족도를 높입니다. 현재는 정상 구독 생성 후 재발송 복제 및 원본 삭제 등 3~4단계의 우회 처리가 필요합니다 (인터뷰 N1, R5). |
| **우선순위** | 높음 |
| **현행지원 여부** | 미지원. 현재 정상 구독 생성→재발송 복제→원본 삭제(3\~4단계) 우회 처리. 선발송 전용 1단계 로직 필요 (**인터뷰 N1, R5**) |

### SB-07: 웹신청자 관리 (홈페이지 접수건 확인·처리)

| 항목 | 내용 |
|------|------|
| **번호** | SB-07 |
| **유형** | 현행 존치 |
| **제목** | 웹신청자 관리 (홈페이지 접수건 확인·처리) |
| **목표** | 홈페이지를 통해 인입된 신규 구독 신청 건을 매일 확인하고 확정하는 업무의 핵심 인터페이스를 제공합니다. |
| **배경** | 비회원 포함 모든 온라인 접수 건을 놓치지 않고 처리하는 현행의 안정적인 관리 환경을 보존하여 업무 연속성을 확보합니다. 현행 존치 대상이며 정기구독팀이 매일 사용하는 고빈도 핵심 메뉴입니다 (메뉴 인벤토리 구독접수 #5). |
| **우선순위** | 필수 |
| **현행지원 여부** | C/S 지원 (PT_Customer, PT_Subscribe). **[현행 존치]** 비회원 포함 홈페이지 신청건을 일별로 확인·처리하는 기능. 정기구독팀이 **매일** 사용하는 핵심 메뉴로, 현행 시스템에서 안정적으로 운영 중. 웹 전환 시 동등 기능 보장 필수 (메뉴 인벤토리 구독접수 #5) |

### SB-08: 월호별 구독만료 조회 및 OB 연계

| 항목 | 내용 |
|------|------|
| **번호** | SB-08 |
| **유형** | 현행 존치 |
| **제목** | 월호별 구독만료 조회 및 OB 연계 |
| **목표** | 월별 만료 고객을 타겟팅하여 아웃바운드(OB) 상담용 리스트를 생성하고 공유하는 프로세스를 지원합니다. |
| **배경** | 정기구독팀과 외주 콜센터 간의 협업 도구로 주 1회 이상 사용되며, 검증된 추출 로직을 통해 만료 안내 활동의 단절을 방지합니다. 현행 존치 대상이며 주 1회 정기적으로 사용하는 핵심 메뉴입니다 (메뉴 인벤토리 구독접수 #7). |
| **우선순위** | 필수 |
| **현행지원 여부** | C/S 지원. **[현행 존치]** 월별 구독만료 대상을 조회한 후 외주 콜센터 OB용 명단을 추출·전달하는 기능. 정기구독팀이 명단을 뽑아 콜센터에 전달하며, 콜센터에서도 직접 조회. **주 1회** 정기적으로 사용하는 핵심 메뉴 (메뉴 인벤토리 구독접수 #7) |
