Giro (bank transfer slip) management handles generation, mailing, and automated payment matching for subscription payments. 
기존 시스템에서 제공하던 지로 생성 및 수납 기능을 웹 환경에 최적화하여 구현하며, 금융결제원 데이터와의 연동성을 강화합니다.

### FR-GR-001: 지로 생성/발송

| 항목 | 내용 |
|------|------|
| **번호** | FR-GR-001 |
| **제목** | 지로 생성/발송 |
| **목표** | 지로 발행 대상자를 선별하고 금융결제원 규격에 맞는 데이터 파일을 생성하여 대량 발송 업무의 정확도를 높입니다. 웹 기반으로 지로 발행 현황을 실시간으로 확인하고 이력을 관리할 수 있는 인터페이스를 구축합니다. |
| **배경** | 기존 시스템의 6개 저장 프로시저(sp_PT_GiroData 등)를 기반으로 안정적인 CRUD 및 파일 생성 로직 이관이 필요합니다. 데이터 생성 및 발송을 위한 통합 기능을 제공하여 업무 효율성을 개선해야 합니다. |
| **우선순위** | 높음 |
| **현행지원 여부** | C/S 지원 (sp_PT_GiroData, sp_PT_GiroAccountData 등 6개 SP). 지로 CRUD + 파일 생성 |

### FR-GR-002: 지로 수납 확인 자동화

| 항목 | 내용 |
|------|------|
| **번호** | FR-GR-002 |
| **제목** | 지로 수납 확인 자동화 |
| **목표** | 금융결제원으로부터 수신한 지로 수납 데이터를 업로드하여 자동으로 입금 처리를 수행하고, 매칭 실패 건에 대한 예외 처리 화면을 제공합니다. |
| **배경** | 현재 sp_PT_GiroFileUpload 등을 통해 부분적으로 지원되나 수동 대조 업무가 병행되고 있습니다. 웹 시스템 전환 시 매칭 로직을 정교화하여 수작업 발생 가능성을 최소화해야 합니다. |
| **우선순위** | 높음 |
| **현행지원 여부** | 부분 지원 (sp_PT_GiroFileUpload). 지로 파일 업로드 → 수납 매칭 존재하나 수동 대조 병행 |

### FR-GR-003: 지로 취소/재발행

| 항목 | 내용 |
|------|------|
| **번호** | FR-GR-003 |
| **제목** | 지로 취소/재발행 |
| **목표** | 발행된 지로의 취소 요청을 처리하고 정보 변경 시 재발행할 수 있는 기능을 제공하며, 지로 상태 변화를 타임라인 형태로 조회할 수 있게 합니다. |
| **배경** | 기존 C/S 시스템의 취소 전용 저장 프로시저(sp_PT_GiroCancel)를 활용하여 데이터 무결성을 보장해야 합니다. 분실이나 정보 수정 대응을 위해 기존 발행 이력과 연계된 관리 체계가 요구됩니다. |
| **우선순위** | 중간 |
| **현행지원 여부** | C/S 지원 (sp_PT_GiroCancel). 취소 SP 존재 |

## 요약
- 지로 생성, 수납, 취소의 전 과정을 웹 기반으로 통합하여 관리 편의성을 향상합니다.
- 금융결제원 데이터 연동 자동화를 통해 정산 업무의 효율성을 높이고 수작업 오류를 방지합니다.
- 기존의 안정적인 DB 로직을 이관하여 시스템 전환에 따른 리스크를 최소화합니다.
