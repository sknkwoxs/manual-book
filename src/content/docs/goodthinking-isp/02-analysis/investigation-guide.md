# 조사 가이드 및 주의사항

ISP 1단계(현황 분석) 수행 전 반드시 확인해야 할 사항과 리스크 대응 전략입니다.

## 현재 상황 요약

| 항목 | 상태 | 리스크 수준 |
|------|------|:----------:|
| XPlatform 소스코드 | 확보 필요 (요청 예정) | 🟠 |
| DB 접근 권한 | 확보 필요 (VPN 접근 선행) | 🟠 |
| DB 정의서 (문서) | ✅ 확보 완료 (C/S + CMS + 홈페이지) | 🟢 |

| 기존 문서 | IT운영 현황, 조직도, 업무플로우 PDF 등 23건 확보 | 🟢 |

## 1. 조사 전 확보해야 할 자료

### 필수 자료 (Must Have)

| 자료 | 요청 대상 | 용도 | 상태 |
|------|----------|------|:----:|
| **DB 스키마 덤프 (DDL)** | 외부 개발자 | 테이블 구조, 관계 파악 | ⬜ (DB 정의서로 대체 분석 완료) |
| **Stored Procedure 목록/코드** | 외부 개발자 | 핵심 비즈니스 로직 파악 | ⬜ (정의서 기반 20 SP 목록 확보) |
| **DB 접속 정보** | 외부 개발자/IT | 직접 데이터 분석 | ⬜ (VPN 접근 선행 필요) |
| **주요 화면 스크린샷** | 정기구독팀 (사용자) | 기능 매핑 | ⬜ |

### 권장 자료 (Should Have)

| 자료 | 요청 대상 | 용도 | 상태 |
|------|----------|------|:----:|

| 시스템 구성도 | 외부 개발자 | 전체 아키텍처 이해 | ✅ (IT운영현황 문서로 확보) |

### 선택 자료 (Nice to Have)

## 2. 리스크 관리: 외부 개발자 협조 제한

### 문제 상황

```mermaid
graph TD
    subgraph canDo["✅ 파악 가능한 것"]
        A1["DB 스키마<br/>(역공학)"]
        A2["테이블 관계<br/>(FK 분석)"]
        A3["데이터 흐름<br/>(데이터 기반 추정)"]
        A4["화면 기능<br/>(사용자 인터뷰)"]
        A5["현재 업무 프로세스"]
    end
    
    subgraph cannotDo["❌ 파악 어려운 것"]
        B1["비즈니스 로직 배경/의도"]
        B2["예외 처리 케이스"]
        B3["히든 기능/암묵적 규칙"]
        B4["'왜 이렇게 만들었는지'"]
        B5["과거 변경 히스토리"]
    end
    
    STRATEGY["📌 전략: 파악 가능한 것에 집중하고,<br/>어려운 것은 사용자 검증으로 보완"]
```

### 대응 전략

#### 전략 1: 역공학 중심 접근

```mermaid
graph LR
    A["DB 스키마 분석<br/>(1)"]
    B["데이터 흐름 추정<br/>(2)"]
    C["사용자 검증<br/>(3)"]
    D["로직 확정<br/>(4)"]
    
    A --> B --> C --> D
```

**단계별 수행 방법**:

| 단계 | 활동 | 산출물 |
|:----:|------|--------|
| 1 | DB 스키마 덤프, 테이블 목록화 | AS-IS ERD (초안) |
| 2 | FK 관계 분석, 데이터 샘플 확인 | 데이터 흐름도 (초안) |
| 3 | 사용자에게 "이렇게 동작하나요?" 검증 | 검증된 데이터 흐름도 |
| 4 | 불명확한 부분은 "추정" 표기 후 진행 | 최종 분석 문서 |

#### 전략 2: 사용자 중심 분석

**실사용자가 개발자보다 더 잘 아는 것**:
- 실제 업무 흐름 (What)
- 예외 상황 대응 방법 (How)
- 현재 시스템의 불편한 점 (Pain Point)
- 꼭 필요한 기능 vs 안 쓰는 기능

**사용자 인터뷰로 파악할 것**:

- [ ] 일일 업무 흐름 시간순
- [ ] 자주 사용하는 화면 기능 Top 5
- [ ] 거의 안 쓰는 기능
- [ ] 예외 상황 처리 방법
- [ ] 수작업으로 하는 것들
- [ ] 가장 불편한 점 Top 3

#### 전략 3: 최소 정보 요청 전략

외부 개발자에게는 **핵심만 요청**:

```mermaid
graph TD
    A["필수 요청 - 1회 요청으로 끝내기"]
    
    B["1. DB 스키마 전체<br/>(DDL export)"]
    C["2. Stored Procedure 전체 코드"]
    D["3. 시스템 전체 구조도<br/>(있다면)"]
    E["4. 외부 연동 방식 설명<br/>(간략히)"]
    F["→ 상세 질문은 하지 않음<br/>→ 받은 자료로 자체 분석 진행"]
    
    A --> B
    A --> C
    A --> D
    A --> E
    A --> F
```

## 3. 역공학 기반 분석 방법

### DB 스키마 분석 절차

```mermaid
graph TD
    A["1. 테이블 목록 추출<br/>SELECT TABLE_NAME<br/>FROM INFORMATION_SCHEMA.TABLES"]
    B["2. 테이블별 컬럼 구조 파악<br/>컬럼명, 데이터타입,<br/>NULL 허용, 기본값"]
    C["3. PK/FK 관계 분석<br/>외래키 기반<br/>테이블 관계도 작성"]
    D["4. 레코드 수 확인<br/>활발히 사용되는<br/>테이블 식별"]
    E["5. 최근 수정일 확인<br/>현재 사용 중인<br/>테이블 식별"]
    
    A --> B --> C --> D --> E
```

### 테이블 분류 기준

| 분류 | 기준 | 분석 우선순위 |
|------|------|:------------:|
| **핵심 테이블** | 레코드 多 + 최근 수정 | ⭐⭐⭐ |
| **참조 테이블** | 코드성 데이터, 변경 적음 | ⭐⭐ |
| **이력 테이블** | 로그성 데이터 | ⭐ |
| **미사용 테이블** | 레코드 0 또는 오래된 수정일 | - |

### 데이터 기반 업무 흐름 추정

```mermaid
graph TD
    subgraph tables["테이블 구조"]
        CUSTOMER["[고객 테이블]<br/>━━━━━━<br/>• 고객ID PK<br/>• 이름<br/>• 연락처"]
        ORDER["[주문 테이블]<br/>━━━━━━<br/>• 주문ID PK<br/>• 고객ID FK<br/>• 주문일자<br/>• 상태코드<br/>• 채널코드"]
        SUB["[구독 테이블]<br/>━━━━━━<br/>• 구독ID PK<br/>• 고객ID FK<br/>• 시작일<br/>• 종료일<br/>• 상태"]
    end
    
    REL["📌 추정: 주문 → 구독 생성<br/>(사용자 검증 필요)"]
    
    CUSTOMER ---|FK| ORDER
    CUSTOMER ---|FK| SUB
    ORDER --> REL
    SUB --> REL
```

## 4. 인터뷰 전략

### 인터뷰 대상별 접근법

#### 외부 개발자 (1회, 30분\~1시간)

**목적**: 전체 구조 파악, 핵심 포인트만 확인

**질문 예시**:
- "시스템 전체 구조를 간략히 설명해 주실 수 있나요?"
- "가장 복잡한 로직이 어디에 있나요?"
- "외부 연동(Playauto, CMS 등)은 어떤 방식으로 하나요?"
- "이 시스템에서 가장 주의해야 할 부분이 있다면?"

**주의사항**:
- 상세 질문 기대하지 않기
- 답변 안 해도 추궁하지 않기
- 받을 수 있는 자료 요청에 집중

#### 실사용자 — 정기구독팀/영업추진팀 (다회, 각 1시간)

**목적**: 실제 업무 흐름, Pain Point 파악

**질문 예시**:
- "하루 업무를 시간순으로 설명해 주세요"
- "이 화면에서 어떤 작업을 하시나요?" (화면 보며)
- "고객 문의가 들어오면 어떤 순서로 처리하시나요?"
- "예외 상황(환불, 오류 등)은 어떻게 처리하시나요?"
- "가장 불편하거나 시간이 오래 걸리는 작업은?"
- "이 기능은 자주 사용하시나요?" (기능별 확인)

**Tip**: 
- 실제 화면을 보면서 진행 (화면 공유 또는 방문)
- 워크 쉐도잉 가능하면 가장 좋음

#### 경영지원팀 (1회, 30분\~1시간)

**목적**: 데이터 활용 현황, 리포트/정산 요구사항

**질문 예시**:
