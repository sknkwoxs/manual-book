# 업무 분석

실무자 워크 쉐도잉을 통해 연동 불가로 인해 발생하는 엑셀 수작업 및 중복 업무 식별

---

## 분석 방법

### 워크 쉐도잉 (Work Shadowing)
실무자의 일상 업무를 관찰하여 실제 업무 흐름과 문제점을 파악

| 대상 | 기간 | 방법 |
|------|------|------|
| CS 담당자 | __일 | 업무 관찰 및 기록 |
| 운영 담당자 | __일 | 업무 관찰 및 기록 |

---

## 현행 업무 흐름도

> 조직도 기반 4개 팀의 업무 플로우를 문서 분석을 통해 정리. 정량 데이터(소요 시간, 건수)는 인터뷰/워크 쉐도잉 후 확정 필요.

### 1. 정기구독팀 (정황규, 어은진) — 5단계

```
① 구독 접수        ② 결제 확인         ③ 발송 처리
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 전화/웹   │───▶│ 나이스페이 │───▶│ CS 프로그램│
│ 구독 신청 │    │ PG 확인  │    │ 발송 데이터│
│ (CS/콜센터)│    │ 지로 확인 │    │  생성     │
└──────────┘    └──────────┘    └────┬─────┘
                                     │
                    ④ 배송 관리       │      ⑤ CS 처리
                ┌──────────┐    ┌────┴─────┐
                │ 우체국/   │◀───│ 발송 지시 │
                │ CJ대한통운│    │ 라벨 출력 │
                └──────────┘    └──────────┘
```

| 단계 | 담당 | 사용 시스템 | 수작업 여부 |
|------|------|-----------|:----------:|
| ① 구독 접수 | 정기구독팀 + 더아이앤오(콜센터) | CS System (XPlatform) | 수동 입력 |
| ② 결제 확인 | 정기구독팀 | 나이스페이 PG + CS System | 수동 확인 |
| ③ 발송 처리 | 정기구독팀 | CS System → SP 호출 | 반자동 |
| ④ 배송 관리 | 정기구독팀 | 우체국/CJ 연동 | 수동 |
| ⑤ CS 처리 | 정기구독팀 + 콜센터 | CS System + CTI | 수동 |

### 2. 영업추진팀 (이성수, 권지은) — 7단계

```
① 주문 수집       ② 주문 확인        ③ 결제 처리
┌──────────┐    ┌──────────┐    ┌──────────┐
│ Playauto │───▶│ Excel    │───▶│ 나이스페이 │
│ (네이버,  │    │ 다운로드  │    │ PG 결제  │
│  쿠팡)    │    │ 수동 확인 │    │ 확인     │
└──────────┘    └──────────┘    └────┬─────┘
                                     │
④ 재고 확인       ⑤ 발송 지시        │
┌──────────┐    ┌──────────┐    ┌────┴─────┐
│ CS 프로그램│◀───│ CS 프로그램│◀───│ CS 입력  │
│ 재고 조회 │    │ 발송 처리 │    │ (수동)   │
└──────────┘    └────┬─────┘    └──────────┘
                     │
⑥ 배송 관리       ⑦ CS/환불
┌──────────┐    ┌──────────┐
│ CJ대한통운│◀───│ CS 처리  │
│ 배송 추적 │    │ 환불/교환 │
└──────────┘    └──────────┘
```

| 단계 | 담당 | 사용 시스템 | 수작업 여부 |
|------|------|-----------|:----------:|
| ① 주문 수집 | 영업추진팀 | Playauto → Excel | **수동** (핵심 병목) |
| ② 주문 확인 | 영업추진팀 | Excel (각 채널 관리자) | **수동** |
| ③ 결제 처리 | 영업추진팀 | 나이스페이 PG | 수동 확인 |
| ④ 재고 확인 | 영업추진팀 | CS System | 수동 조회 |
| ⑤ 발송 지시 | 영업추진팀 | CS System | 반자동 |
| ⑥ 배송 관리 | 영업추진팀 | CJ대한통운 | 수동 |
| ⑦ CS/환불 | 영업추진팀 | CS System + 나이스페이 | 수동 |

### 3. 경영지원팀 (송윤경, 김나현) — 5단계

```
① 매출 관리       ② 정산 처리        ③ 세금계산서
┌──────────┐    ┌──────────┐    ┌──────────┐
│ CS 프로그램│───▶│ Excel    │───▶│ 이카운트  │
│ 매출 집계 │    │ 수동 취합 │    │ ERP 입력 │
│ (수동 조회)│    │ 나이스페이 │    │ (이중 입력)│
└──────────┘    │ 정산 확인 │    └────┬─────┘
                └──────────┘         │
                                     │
④ 기안/결재                     ⑤ 월결산
┌──────────┐                ┌──────────┐
│ 이카운트  │◀───────────────│ 이카운트  │
│ 기안 작성 │                │ 월 마감  │
│ 전자결재  │                │ 보고서   │
└──────────┘                └──────────┘
```

| 단계 | 담당 | 사용 시스템 | 수작업 여부 |
|------|------|-----------|:----------:|
| ① 매출 관리 | 경영지원팀 | CS System → Excel | **수동** (핵심 병목) |
| ② 정산 처리 | 경영지원팀 | Excel + 나이스페이 | **수동** |
| ③ 세금계산서 | 경영지원팀 | 이카운트 ERP (이중 입력) | **수동** (이중 작업) |
| ④ 기안/결재 | 경영지원팀 | 이카운트 ERP | 수동 |
| ⑤ 월결산 | 경영지원팀 | 이카운트 ERP + Excel | 수동 |

### 4. 앵두아트프로젝트 — 7단계

```
① 기획           ② 제작            ③ 재고 관리
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 상품 기획 │───▶│ 디자인/  │───▶│ CS 프로그램│
│ (아트상품) │    │ 제작     │    │ 재고 등록 │
└──────────┘    └──────────┘    └────┬─────┘
                                     │
④ 판매            ⑤ 주문 처리       │
┌──────────┐    ┌──────────┐    ┌────┴─────┐
│ 홈페이지  │◀───│ 관리자   │◀───│ 상품 등록 │
│ + 외부몰  │    │ 주문 확인│    │          │
└──────────┘    └────┬─────┘    └──────────┘
                     │
⑥ 배송            ⑦ 정산
┌──────────┐    ┌──────────┐
│ CJ대한통운│◀───│ 매출 취합│
│ 발송     │    │ 정산 처리│
└──────────┘    └──────────┘
```

| 단계 | 담당 | 사용 시스템 | 수작업 여부 |
|------|------|-----------|:----------:|
| ① 기획 | 앵두아트 | - | - |
| ② 제작 | 앵두아트 | - | - |
| ③ 재고 관리 | 앵두아트 | CS System | 수동 |
| ④ 판매 | 앵두아트 | 홈페이지 Admin + 외부몰 | 수동 등록 |
| ⑤ 주문 처리 | 앵두아트 | Admin + Playauto | 수동 |
| ⑥ 배송 | 앵두아트 | CJ대한통운 | 수동 |
| ⑦ 정산 | 앵두아트 + 경영지원 | Excel + 이카운트 | 수동 |

### 5. 주문 처리 프로세스 (통합 뷰)

## 수작업 구간 식별

### 식별된 수작업 항목

| No | 업무 | 현재 방식 | 소요 시간 | 빈도 | 오류 위험 |
|----|------|----------|----------|------|----------|
| 1 | 주문 데이터 다운로드 | 각 채널 수동 접속 | __분 | 일 __회 | 중 |
| 2 | Excel 데이터 취합 | 수동 복사/붙여넣기 | __분 | 일 __회 | 상 |
| 3 | CS 프로그램 입력 | 건별 수동 입력 | __분/건 | 일 __건 | 상 |
| 4 | CMS 권한 부여 | 별도 시스템 수동 처리 | __분/건 | 일 __건 | 중 |
| 5 | 데이터 검증 | 목시 확인 | __분 | 일 __회 | 상 |

### 수작업으로 인한 문제

1. **시간 낭비**
   - 일일 수작업 총 소요 시간: __시간 (추정)
   - 월간 환산: __시간

2. **오류 발생**
   - 입력 오류 발생 건수: 월 __건 (추정)
   - 오류 수정 소요 시간: __시간/건

3. **업무 집중도 저하**
   - 단순 반복 업무로 인한 피로 누적
   - 본질적 CS 업무에 투입 시간 감소

## 병목 구간 분석

### 주요 병목 지점

```
병목 심각도: 🔴 높음 | 🟠 중간 | 🟢 낮음

1. [주문 수집 → CS 입력]  🔴
   - 원인: 시스템 간 연동 불가
   - 영향: 처리 지연 __시간

2. [결제 확인 → 권한 부여]  🔴
   - 원인: CMS와 CS 분리
   - 영향: 고객 이용 지연

3. [데이터 취합]  🟠
   - 원인: 다중 채널 수동 접속
   - 영향: 일 __시간 소요
```

### 병목 해소를 위한 개선 방향

| 병목 | 현재 | 개선 방향 |
|------|------|----------|
| 주문 수집 | 수동 다운로드 | API 자동 연동 |
| 데이터 입력 | 수동 입력 | 자동 입력/동기화 |
| 권한 부여 | 수동 처리 | 결제 연동 자동화 |

## 업무 분석 체크리스트

### 주문처리 프로세스
- [ ] 채널별로 주문 처리 과정이 다른지? 어디서 갈라지는지?
- [ ] Playauto의 정확한 역할 — 주문 수집만? 결제 확인도?
- [ ] 결제 확인 → 권한 부여까지 실제 소요 시간?
- [ ] 수작업이 발생하는 단계는?
- [ ] 가장 시간이 오래 걸리는 단계는?
- [ ] 담당자 부재 시 멈추는 단계가 있는지?

### 데이터 취합 프로세스
- [ ] 취합 주기는? (일간/주간/월간?)
- [ ] 한 번 취합 시 데이터 양은?
- [ ] 채널별 데이터 형식이 다른지?
- [ ] 통합 시 기준 키(고객ID 등)는 무엇인지?
- [ ] 수작업이 발생하는 단계는?
- [ ] 오류가 자주 발생하는 단계는?

### CS(고객서비스) 처리 흐름
- [ ] 문의 접수 경로 (전화, 이메일, 기타)
- [ ] 고객 정보 조회 시 사용하는 시스템
- [ ] 주문/결제 관련 문의 처리 시, 주문처리 프로세스의 어느 단계를 참조하는지
- [ ] 내부 CS팀과 외주 콜센터(더아이앤오)의 업무 분담 기준

### 문서 기반 추정 검증
- [ ] 주문 수집: Playauto → Excel 다운로드 → CS 프로그램 수동 입력 — 실제 맞는지?
- [ ] 데이터 취합: 각 채널별 관리자 로그인 → Excel 다운 → 수기 통합 — 실제 맞는지?
- [ ] 권한 부여: 결제 확인 후 CMS에 별도 접속하여 수동 처리 — 실제 맞는지?
- [ ] CS 시스템(MSSQL)과 웹 시스템(MSSQL, AWS)은 완전 분리, 연동 없음 — 실제 맞는지?
- [ ] 위 추정 외에 우리가 모르는 수작업 구간이 있는지?
- [ ] 우리가 파악하지 못한 시스템이나 도구가 있는지?
