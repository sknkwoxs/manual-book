## 인터뷰 개요

### 목적
1. **현행 업무 파악**: 실제 업무 수행 방식과 흐름 이해
2. **문제점 도출**: 현 시스템/프로세스의 불편사항 및 개선점 파악
3. **요구사항 수집**: 신규 시스템에 필요한 기능 및 개선 요청 취합

## 인터뷰 질문 가이드

:::note[질문 구성 원칙]
대상자의 **구분/역할**에 맞는 맞춤형 질문으로 구성했습니다.
- **공통 질문 (C1\~C3)**: 전 대상자 공통
- **유형별 질문 (A\~G)**: 역할에 따라 해당 유형만 질문
  - A: 정기구독팀 (정황규, 어은진) · B: 영업추진팀 (이성수, 권지은) · C: 경영지원팀 (송윤경, 김나현)
  - D: 편집팀 (정다정, 이민애, 김혜원) · E: IT/시스템 (김재옥) · F: CEO (정용철) · G: 외부콜센터 (더아이앤오)
- **업무 분석 검증 (V)**: 업무 분석 문서의 추정 내용을 현장 확인하는 질문 (유형별 3\~5개)
- **워크쉐도잉 확인사항 (WS)**: 실무자(유형 A/B/C/D/G) 워크쉐도잉 시 관찰·측정할 체크리스트
- 총 질문 수: 대상자당 **10\~12개** (공통 2 + 유형별 5 + 검증 3\~5)
:::

- [ ] 담당자 부재 시 **업무가 멈추는 단계**가 있는지 확인

### 유형 G: 외부콜센터 — 더아이앤오(\~4명)

| # | 질문 | 검증 대상 |
|---|------|----------|
| G1 | VPN으로 CS System에 접속해서 업무를 처리하실 때, **접속 속도나 화면 반응** 문제가 있나요? | 외부 접근성 문제 파악 |
| G2 | 하루 평균 몇 건의 CS를 처리하시고, 가장 많은 **문의 유형** (구독/배송/환불/기타)은 무엇인가요? | CS 업무량 및 유형 분포 파악 |
| G3 | 고객 응대 시 **고객 정보를 조회하는 과정**은 어떻게 되나요? 필요한 정보가 한 화면에 나오나요, 여러 곳을 찾아봐야 하나요? | 고객 정보 조회 효율성 |
| G4 | CS 처리 결과를 **좋은생각사람들 내부 팀에 전달**하는 방식은 무엇인가요? (시스템 내 기록 / 별도 보고 / 유선 등) | 외부↔내부 커뮤니케이션 방식 |
| G5 | 현재 CS System에서 **처리할 수 없어서 내부 직원에게 넘겨야 하는 업무**가 있나요? 어떤 유형이 가장 많나요? | 콜센터 권한 범위 및 에스컬레이션 파악 |

#### 유형 G 업무 분석 검증 (외부콜센터)

> 아래 질문은 [업무 분석](/goodthinking-isp/02-analysis/business-analysis/) 문서의 추정 내용을 검증합니다.

| # | 질문 | 검증 대상 (업무 분석 참조) |
|---|------|--------------------------|
| VG1 | 저희 분석에서 콜센터는 **일반 문의를 처리**하고, 결제/구독 변경 등은 **내부팀으로 에스컬레이션**하는 것으로 파악했는데 맞나요? 그 기준이 명확히 정해져 있나요? | 체크리스트: 내외부 업무 분담 기준 확인 |
| VG2 | CS System에 **주문 데이터를 직접 입력**하시는 경우가 있나요? 있다면 건당 소요 시간과 하루 몇 건 정도인가요? | 수작업 #3 (콜센터 측 CS 입력 분담) 확인 |
| VG3 | 고객 문의 응대 중 CS System에서 **필요한 정보를 찾지 못해** 내부 직원에게 확인 요청하는 경우가 하루에 몇 건 정도인가요? | 고객 360° 뷰 부재가 콜센터에 미치는 영향 |

## 인터뷰 진행 시 주의사항

### Do's (해야 할 것)

- **경청하기**: 말을 끊지 않고 끝까지 듣기
- **구체적으로 묻기**: "불편하다"면 → "어떤 상황에서, 어떻게 불편한지" 추가 질문
- **예시 요청하기**: "예를 들어 설명해 주실 수 있나요?"
- **화면 보며 진행**: 가능하면 실제 화면을 보면서 인터뷰
- **녹음/녹화 동의**: 사전에 녹음 동의 받기 (기록 정확성 위해)

### Don'ts (하지 말아야 할 것)

- **유도 질문 피하기**: "이 기능이 필요하시죠?" (X) → "어떤 기능이 필요하신가요?" (O)
- **기술 용어 사용 자제**: 사용자 눈높이에 맞춰 질문
- **한 번에 여러 질문 피하기**: 질문은 하나씩
- **답변 해석하지 않기**: 들은 그대로 기록

### 협조가 어려운 경우 대응

| 상황 | 대응 방법 |
|------|----------|
| 바쁘다고 함 | 15분만이라도 요청, 핵심 질문만 |
| 모른다고 함 | "평소에 어떻게 하시나요?"로 우회 |
| 기존 시스템 옹호 | 공감 후 "더 좋아지면 하는 점" 질문 |
| 부정적 반응 | 변화의 이점 설명, 의견 존중 표현 |
