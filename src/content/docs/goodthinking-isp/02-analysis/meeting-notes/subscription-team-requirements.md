## 기능요건 상세

### SUB-001

| 항목 | 내용 |
|------|------|
| **번호** | SUB-001 |
| **제목** | 개인정보 자동 파기 |
| **내용** | 개인정보 보유 기간 경과 또는 처리 목적 달성 시, 해당 고객 정보를 **자동으로 휴면처리·재동의 요청·마스킹 처리**하는 기능을 구현한다. 파기 대상 목록 자동 추출, 파기 이력 관리(일시·항목·처리자), 파기 전 알림 및 재동의 프로세스를 포함한다. |
| **배경** | 현재 5년 경과 개인정보의 자동 삭제 기능이 없어, 매월 과거 만료자를 엑셀로 추출하여 **일일이 눈으로 대조하며 삭제**하는 수작업을 진행 중. 정기구독팀에서 **가장 급한 법적 리스크**로 인식하고 있으며, 개인정보보호법 위반 가능성이 상존. (R1, N4) |
| **관련 시스템** | CS 시스템 |
| **관련 메뉴** | 관리자업무 > 회원 현황 |
| **관련 부서** | 정기구독팀, 경영지원팀 |

:::caution[법적 리스크]
개인정보보호법상 보유 기간 경과 시 지체 없이 파기해야 하며, 현재 수동 처리 방식은 누락 위험이 높아 **최우선 구현 대상**입니다.
:::

### SUB-002

| 항목 | 내용 |
|------|------|
| **번호** | SUB-002 |
| **제목** | 결제·회계 시스템 API 연동 |
| **내용** | ① 나이스페이 API를 통해 **4~5개 분산 계정의 결제 내역을 CS 시스템에서 통합 조회**하고, 카드 결제 취소를 CS 시스템 내에서 즉시 처리할 수 있도록 한다. ② 위하고(WEHAGO) API 연동으로 매출·수금 데이터를 자동 전송하여 이중 입력을 제거한다. |
| **배경** | 결제 출처별 4~5개의 개별 나이스페이 계정을 번갈아 접속해야 하며, 카드 취소 시 해당 계정을 찾아 직접 처리. 동일 데이터를 CS 시스템과 위하고 양쪽에 각각 입력하는 이중 작업 발생. (R2, N6) |
| **관련 시스템** | CS 시스템, 나이스페이, 위하고(WEHAGO) |
| **관련 메뉴** | 입금관리 > 카드결제관리, 입금관리 > 가상계좌관리 |
| **관련 부서** | 정기구독팀, 경영지원팀, 콜센터 |

### SUB-004

| 항목 | 내용 |
