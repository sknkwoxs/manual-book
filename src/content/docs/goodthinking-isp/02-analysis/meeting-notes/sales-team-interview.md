## 인터뷰 목적

영업추진팀의 다채널 주문 처리 프로세스를 현장 확인하고 애로사항을 청취합니다.

1. **다채널 주문 수집·처리** — Playauto를 통한 외부몰 주문 수집, Excel 가공, CS 시스템 입력까지의 전 과정 확인
2. **총판/다량/특판 주문 관리** — 일반 주문과 구분되는 B2B 주문 처리 흐름 및 특수 프로세스 파악
3. **재고·배송 관리** — 재고 확인 방식, 발송 지시, 배송 추적까지의 물류 프로세스 확인
4. **CS/환불 처리** — 반품·교환·환불 시 Playauto↔CS 시스템 이중 처리 여부 및 정기구독팀 업무 경계 확인

:::note[업무 분석 연계]
본 인터뷰 안건은 [업무 분석](/goodthinking-isp/02-analysis/business-analysis/) 문서의 영업추진팀 7단계 워크플로(주문 수집→주문 확인→결제 처리→CS 입력→재고 확인→발송 지시→배송 관리→CS/환불), 수작업 #1~#3, #7, 병목 ①②④와 연계된 검증 질문을 포함합니다. 상세 질문지는 [인터뷰 질문지 — 유형 B](/goodthinking-isp/02-analysis/interview/#유형-b-영업추진팀--이성수관리-권지은실무)를 참조하세요.
:::

## 안건 1. 다채널 주문 수집·확인 프로세스

**목표**: Playauto 및 각 판매 채널에서 주문을 수집하고 확인하는 전 과정을 파악하고, 채널별 처리 차이와 소요 시간을 검증

### 핵심 질문 요약

| # | 질문 요약 | 검증 대상 |
|---|----------|----------|
| B1 | Playauto에서 주문을 Excel로 다운받아 CS System에 수동 입력하는 과정 및 일일 건수·소요 시간 | Playauto→Excel→CS 수동이관 병목 ①, 수작업 #1 |
| B2 | 채널별(쿠팡/네이버/카카오 등) 관리자 페이지에 따로 로그인하여 주문/CS를 처리하는지, 채널 간 데이터 통합 방식 | 채널별 분산 관리 병목 ②④ |
| C1 | 담당 주요 업무와 하루 흐름, 가장 불편하거나 시간이 많이 걸리는 부분 | 역할 파악 + 핵심 페인포인트 도출 |

### 상세 질문

#### 1-1. Playauto 주문 수집

- [ ] Playauto에서 주문을 가져올 때, **Excel로 다운받아 CS System에 수동 입력**하는 과정이 맞는지 확인
- [ ] 하루에 몇 건 정도 처리하고, 한 건당 얼마나 걸리는지 확인
- [ ] Playauto에서 수집하는 **외부몰 목록** 확인 (정기구독팀과 동일한 10개 몰인지, 또는 별도 채널이 있는지)
- [ ] Playauto **미연동 채널**(나이스북, 더매거진 등)의 주문은 어떻게 처리하는지 확인

:::note[정기구독팀 인터뷰 교차 검증]
정기구독팀 인터뷰(2026-03-17)에서 정황규 매니저가 Playauto를 통해 **외부몰 10개** 주문을 수집하고 있음을 확인. 영업추진팀이 동일한 Playauto 계정을 공유하는지, 별도 계정인지, 또는 정기구독팀이 수집한 데이터를 전달받는 방식인지 확인 필요.
:::

#### 1-2. 채널별 주문 확인

- [ ] 쿠팡/네이버/카카오 등 **채널별로 관리자 페이지에 따로 로그인**해서 주문/CS를 처리하는지 확인
- [ ] 채널 간 데이터 통합은 어떻게 하는지 (Playauto에서 통합? 별도 Excel 취합?)
- [ ] 자사몰(goodthink.co.kr) 주문은 어떤 경로로 확인하는지 (홈페이지 Admin? 별도 방법?)

#### 1-3. 정기구독팀과의 업무 분담

- [ ] 정기구독팀(정황규, 어은진)과 **동일한 채널의 주문을 나눠서 처리**하는지, 완전히 분리된 채널을 담당하는지 확인
- [ ] Playauto 계정을 공유하는지, 별도 계정을 사용하는지 확인
- [ ] 정기구독 상품과 영업추진팀 상품(단행본, 특판 등)의 **주문 구분 기준** 확인

## 안건 2. Excel 데이터 가공 및 CS 시스템 입력

**목표**: 수집된 주문 데이터를 CS 시스템에 등록하기까지의 Excel 가공 과정과 소요 시간을 파악하고, 채널별 양식 차이로 인한 수작업 부담을 확인

### 핵심 질문 요약

| # | 질문 요약 | 검증 대상 |
|---|----------|----------|
| VB3 | 채널별 Excel 데이터 형식 차이 및 통합 시 가장 번거로운 부분 | 수작업 #2 Excel 취합 검증 |
| VB4 | 홈페이지 Admin 주문 → CS System 수동 재입력 과정 및 건수·소요 시간 | 수작업 #7 홈페이지 주문 이관 검증 |
| VB5 | 수작업 입력 중 오류가 가장 자주 발생하는 단계 및 오류 수정 소요 시간 | 오류 빈발 단계 확인 |

### 상세 질문

#### 2-1. Excel 양식 표준화 작업

- [ ] 채널별(네이버/쿠팡/자사몰) **Excel 데이터 형식이 각각 다른** 것으로 파악 — 통합 시 가장 번거로운 부분 확인
- [ ] 형식 맞추는 데 별도 시간이 드는지, 정기구독팀의 **어드민 업로드 규격**과 동일한 양식을 사용하는지 확인
- [ ] 표준화 작업 시 주소 분리, 열 맞춤 등의 가공 과정이 있는지 확인

#### 2-2. CS 시스템 등록

- [ ] 홈페이지 Admin에서 주문 확인 후 CS System에 **수동 재입력**하는 과정 확인 (추정: 건당 5~10분, 일 5~10건)
- [ ] CS 시스템에 등록할 때 **일괄 업로드** 방식인지, **건별 수동 입력** 방식인지 확인
- [ ] 등록 후 데이터 검수(육안 확인) 과정이 있는지 확인

#### 2-3. 수작업 오류 발생

- [ ] 수작업 입력 중 **오류가 가장 자주 발생하는 단계** 확인 (주문 수집? Excel 가공? CS 입력?)
- [ ] 오류 발견 시 수정에 얼마나 걸리는지 확인
- [ ] 오류로 인한 배송 오류, 결제 불일치 등 실제 사고 사례 확인

## 안건 3. 총판/다량/특판 주문 처리

**목표**: 영업추진팀 고유 업무인 총판·다량·특판 주문의 처리 흐름을 파악하고, 일반 개인 주문과의 프로세스 차이를 확인

### 핵심 질문 요약

| # | 질문 요약 | 검증 대상 |
|---|----------|----------|
| B3 | 총판/다량/특판 주문은 일반 주문과 처리 흐름이 어떻게 다른지, 별도 양식 사용 여부 | 특수 주문 프로세스 파악 |

### 상세 질문

#### 3-1. 총판/다량/특판 주문 유형 분류

- [ ] **총판**: 어떤 업체가 있는지, 주문 접수 방식(전화/이메일/시스템), 계약 및 가격 구조
- [ ] **다량 주문**: 기관·기업 대량 구매 건의 접수·처리 흐름, 별도 할인 정책 여부
- [ ] **특판**: 특수 판매 채널(한화, 교보, 삼성 등 기업 제휴) 주문 처리 과정
- [ ] 각 유형별 **월 평균 건수 및 매출 비중** 파악

#### 3-2. 일반 주문과의 프로세스 차이

- [ ] 총판/다량/특판 주문에 **별도 양식(Excel 등)**을 사용하는지 확인
- [ ] 결제 방식 차이 (계좌이체? 세금계산서 후불? 나이스페이?)
- [ ] CS 시스템에서 일반 주문과 **동일 메뉴로 처리**하는지, 별도 프로세스가 있는지

#### 3-3. 오프라인 서점 관리

- [ ] 오프라인 서점(교보, 영풍문고 등) 납품 주문 처리 방식
- [ ] 서점 반품 처리 프로세스 및 정산 방식
- [ ] 서점과의 데이터 교환 방식 (시스템? Excel? 전화/팩스?)

## 안건 4. 재고 확인 및 발송 처리

**목표**: 주문 확인 후 재고 조회부터 발송 지시까지의 물류 프로세스를 파악하고, 재고 관리의 실시간성과 정확도를 확인

### 핵심 질문 요약

| # | 질문 요약 | 검증 대상 |
|---|----------|----------|
| B4 | 재고 확인 방식 — CS System 실시간 확인 가능 여부, 별도 확인 필요 여부 | 재고 관리 현황 파악 |

### 상세 질문

#### 4-1. 재고 확인

- [ ] 재고 확인은 CS System에서 **실시간으로 확인 가능**한지, 별도 시스템(WEHAGO, 물류 창고 문의 등)이 필요한지 확인
- [ ] 재고가 부족한 경우 주문 처리 프로세스는 어떻게 되는지 (대기? 취소? 발주?)
- [ ] 월간지 외 단행본·사은품 재고도 동일 시스템에서 관리하는지 확인

:::note[정기구독팀 인터뷰 교차 검증]
정기구독팀 인터뷰에서 WEHAGO/CS 시스템/물류 창고 간 **재고 수치 불일치** 문제가 확인됨 (매월 말 임의 수치 조정). 영업추진팀에서도 동일한 재고 불일치 문제를 경험하는지, 재고 확인 시 어느 시스템의 수치를 기준으로 삼는지 확인 필요.
:::

#### 4-2. 발송 지시 및 배송 관리

- [ ] 발송 지시는 CS System에서 처리하는지, 별도 절차가 있는지 확인
- [ ] 배송 업체 (CJ대한통운? 우체국? 복수?) 및 송장 번호 관리 방식
- [ ] 배송 추적 정보를 외부몰(네이버/쿠팡)에 **자동 전송**하는지, 수동 입력하는지 확인
- [ ] Playauto를 통해 **배송 상태를 외부몰에 전달**하는 기능을 사용하는지 확인

## 안건 5. 반품/교환/환불 처리

**목표**: 배송 완료 후 발생하는 반품·교환·환불 처리 시 Playauto와 CS 시스템 양쪽 처리 여부를 확인하고, 이중 처리로 인한 누락·오류 리스크를 파악

### 핵심 질문 요약

| # | 질문 요약 | 검증 대상 |
|---|----------|----------|
| B5 | 반품/교환/환불 처리 시 Playauto와 CS System 양쪽 모두 처리 필요 여부, 누락 발생 여부 | 반품/환불 이중 처리 병목 |

### 상세 질문

#### 5-1. 반품/교환 처리

- [ ] 반품 접수 경로 (외부몰 자동? CS 전화? 양쪽 모두?)
- [ ] Playauto와 CS System **양쪽 모두 따로 처리**해야 하는지, 한쪽만 처리하면 동기화되는지 확인
- [ ] 반품 후 재고 반영은 자동인지, 수동 처리인지 확인

#### 5-2. 환불 처리

- [ ] 환불 시 결제 수단별(카드/계좌이체/가상계좌) 처리 방식 차이
- [ ] 나이스페이 계정 접속이 필요한지 (정기구독팀과 동일한 4~5개 나이스페이 계정을 사용하는지 확인)
- [ ] 환불 처리 후 외부몰 상태 변경까지의 과정 (Playauto 자동? 수동?)

:::note[정기구독팀 인터뷰 교차 검증]
정기구독팀에서 확인된 **나이스페이 4~5개 계정 분산** 문제가 영업추진팀에서도 동일하게 발생하는지 확인 필요. 영업추진팀이 사용하는 나이스페이 계정이 정기구독팀과 동일한 계정인지, 별도 계정인지 확인.
:::

#### 5-3. 누락 및 오류 사례

- [ ] Playauto와 CS System 간 **데이터 불일치**로 인한 문제 사례 확인
- [ ] 환불 처리 누락으로 고객 불만이 발생한 사례 여부
- [ ] 이중 처리 방지를 위한 체크 절차가 있는지 확인

## 안건 6. 정기구독팀과의 업무 경계 확인

**목표**: 영업추진팀과 정기구독팀 간 업무 분담의 명확한 경계를 파악하고, 중복·누락 구간을 식별

### 상세 질문

- [ ] 정기구독팀(정황규, 어은진)과의 **일상적인 업무 협업 사항**은 무엇인지
- [ ] 동일 채널(예: 네이버 스마트스토어)에서 정기구독 상품과 영업추진 상품이 **섞여서 들어올 때** 어떻게 분류·처리하는지
- [ ] CS 문의가 들어왔을 때 **정기구독 건인지 영업추진 건인지 구분하는 기준**은 무엇인지
- [ ] 외주콜센터(더아이앤오)에서 **영업추진팀으로 에스컬레이션**되는 건이 있는지, 어떤 유형인지
