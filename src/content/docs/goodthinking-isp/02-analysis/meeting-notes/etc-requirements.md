## 기능요건 상세

### SUB-011

| 항목 | 내용 |
|------|------|
| **번호** | SUB-011 |
| **제목** | 시스템 구축 컨셉 정리 |
| **내용** | 어드민/CMS/CS 시스템의 **통합 vs 분리 구축 방안**을 검토한다. ① 3개 시스템 완전 통합, ② 어드민+CMS 통합 + CS 시스템 강화, ③ 각 시스템 역할 재정의 후 API 연동 — 3개 옵션을 비교 분석한다. |
| **배경** | 어드민에 CS 시스템 기능이, CS 시스템에 어드민 기능이 혼재되어 있어 업무 흐름이 비효율적. 주문/구독 업로드 관리 등 CS 시스템에 있어야 할 기능이 어드민에 위치. ([R9](/goodthinking-isp/02-analysis/meeting-notes/subscription-team-interview/#시스템-기능-개선-요구사항)) |
| **관련 시스템** | CS 시스템, 어드민, CMS |
| **관련 메뉴** | - |
| **관련 부서** | 전체 부서 |

:::tip[아키텍처 결정 사항]
이 기능요건은 특정 시스템이 아닌 **전체 시스템 아키텍처에 대한 방향 설정**으로, ISP 3단계(목표 모델 설계)에서 상세 검토됩니다.
:::

### MGT-005

| 항목 | 내용 |
|------|------|
| **번호** | MGT-005 |
| **제목** | 매출 원가 관리 모듈 |
| **내용** | 개별 도서·프로젝트별 **투입 비용(인쇄비, 종이값, 인건비 등)과 매출을 한눈에 비교**할 수 있는 원가 관리 기능을 구현한다. ① 지출결의서·견적서 데이터 연동, ② 프로젝트별 BEP(손익분기점) 자동 산출, ③ 은행 이체와 동시에 비용 업로드하여 실시간 원가 파악을 목표로 한다. |
| **배경** | 특정 도서를 제작할 때 투입된 비용과 매출을 한눈에 비교할 수 있는 **시스템이 없음**. 세무법인·위하고에서는 전체 매출 기준으로만 관리하므로, 개별 도서별 수익성 판단(추가 인쇄 여부 등)이 어려움. 원 데이터(지출결의서·견적서)의 정확성 확인이 선행되어야 함. ([R2](/goodthinking-isp/02-analysis/meeting-notes/management-support-team-interview/#시스템-기능-개선-요구사항)) |
| **관련 시스템** | 위하고(WEHAGO), CS 시스템 |
| **관련 메뉴** | 신규 메뉴 필요 |
| **관련 부서** | 경영지원팀, 편집팀, 단행본팀 |

:::caution[구현 전제조건]
원가 관리 기능 도입 시 **지출결의서 및 견적서 등의 원 데이터 정확성 확인이 필수적**입니다. 경영지원팀이 인터뷰에서 직접 언급한 전제조건입니다.
:::

:::note[논의 사항]
- **자동화의 난이도**: 인쇄비, 종이값 등 건건이 금액이 달라지거나 수동 수정이 필요한 항목이 많아, 완전 자동화보다는 시스템이 계산을 보조하는 형태가 현실적이라는 의견이 많았습니다.
- **재고 및 판매 데이터 연동**: 원가를 정확히 산출하려면 외부 총판이나 서점의 실시간 재고 및 판매 데이터가 연동되어야 하는데, 현재는 엑셀 수작업에 의존하고 있어 시스템 구현 시 이 간극을 어떻게 메울지가 관건입니다.
- **개발 범위 결정 필요**: 원가 관리 기능을 실제 개발 범위에 포함할지, 아니면 우선순위에서 조정할지 결정이 필요합니다.
:::
