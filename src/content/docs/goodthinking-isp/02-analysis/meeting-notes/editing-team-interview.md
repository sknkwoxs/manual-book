## 안건 1. 원고 응모 관리 (홈페이지 어드민)

**목표**: 홈페이지 어드민에서의 원고 접수·분류·처리 프로세스를 파악하고, 공모전 대량 원고 처리의 수작업 부담을 검증

### 핵심 질문 요약

| # | 질문 요약 | 검증 대상 |
|---|----------|----------|
| D1 | 신규 원고 확인·다운로드 과정 및 소요 시간 | 원고 접수 처리 흐름 정량 파악 |
| D2 | 상시 모집 vs 공모전 원고 구분 방식 | 원고 유형별 분류 체계, 수작업 #16 |
| D3 | 원고 상태 변경 단계 및 작성자 통보 방식 | 상태 관리 워크플로 + 알림 자동화 수준 |
| D4 | 공모전 대량 원고 배분 기준·방식 | 수작업 #16 공모전 원고 관리 정량 |

### 인터뷰 결과

#### 1-1. 온라인 원고 응모 관리

- 어드민 로그인 → 원고 목록 → 다운로드 흐름 화면 시연 확인 (완료)
- 월평균 접수 규모 및 처리 방식 확인 (완료)

**원고 접수 규모 및 채널** (이민애 편집장):
- 웹사이트, 우편, 팩스 등을 통해 월평균 **700~800편**의 원고 접수
- 응모가 끝난 뒤 채택을 거쳐 발행된 원고의 최종본은 CMS로 이동 — 즉, **응모 원고는 어드민에 보관**

**원고 유형 구분** (이민애 편집장):
- 좋은생각에 실리는 원고는 **필자글**과 **독자글**로 구분
  - **필자글**: 기자들이 기획 및 청탁 진행, 약 23편 게재, 필자 총 13명. 연재 필자는 정기적으로 **6개월씩 계약**하여 기자별로 담당
  - **독자글**: 코너별(인류의 충전, 군대 이야기 등) 독자 글을 월간지 팀에서 발굴. 일반독자 약 21명
- 총 원고 기준 **월 75~80편** 게재

#### 1-2. 오프라인 원고 응모 관리

- 오프라인 원고 보관 방식 및 규모 확인 (완료)

**오프라인 원고 보관 현황**:
- 우편/팩스 등 오프라인 원고는 따로 모아두며, 채택되지 않은 원고는 **시스템적으로 보존하지 못하는 상태**
- 최근에는 캐비넷에 박스별로 잠시 보관 후 **스캔 → 폐기** 방식으로 진행
- 디자인팀 방에 다량의 수기 원고가 들어있는 상자가 보존됨
- 우편/팩스 원고는 기자가 직접 스캔하여 **기자 PC나 NAS에 보관** 중이나 어드민이나 CMS에는 저장하지 않은 상태

**정다정 연구소장**: 총 **약 40박스** 보유 중이며, 1박스 당 500~600편 보존 가능. 오프라인 원고까지 포함하면 약 **7천 편** 보존 추정

#### 1-3. 원고 배분 및 검토

- 공모전별 접수 규모 및 배분 방식 확인 (완료)
- 검토 프로세스 및 기자당 업무량 확인 (완료)

**배분 프로세스** (이민애 편집장):
- 전체적으로는 모든 인원이 원고를 검토하되, **특집별로 각 기자가 맡은 파트에 맞춰** 원고를 관리
- 공동으로 원고를 보는 경우(좋은님 에세이 등)는 어드민에서 원고를 검색해 **기자별 N분의 1로 배분**
- 한 기자당 월 검토 원고 약 **250개**

**검토 일정** (이민애 편집장):
- 현 일정(3월) 기준 11일까지 독자 글 제출일이며, 12일 전까지 모두 원고를 검토 완료해야 하므로 **2월 마지막 주에 바로 원고 검토 시작**
- 원고 검토는 반드시 **1명의 기자가 전담** 진행

> **[주의]** 배분 수작업 이슈
>
> 배분 작업은 어드민에서 처리하는 것보다 **수기로 처리하여 관리**하는 방식. 시스템 상에서 배분 시 **담당 기자를 지정하는 기능이 없음**. → 개선 요구사항 R3 (원고 관리 기능 강화)

#### 1-4. 원고 평가 및 채택

- 원고 상태값 목록 확인 (완료)
- 상태 변경 시 작성자 통보 방식 확인 (완료)

**원고 평가 프로세스** (이민애 편집장):
- **필자글**: 기자별 청탁 리스트를 편집장이 받아 채택 결정. 청탁 필자 글이 들어오면 직접 검수 후 채택 여부 검토 (독자글도 동일)
- **독자글**: 내부 선별 기준에 따라 점수를 매김. 문예대상 등의 원고 평가표 기준으로 2배수 선별 후 최종 게재 원고 확정
  - *(공모전 원고 평가표 열람 — 향후 양식파일 전달 예정)*
- 이번 달에 게재할 글이 없다고 판단되면 생활문예대상·청년이야기대상 **당선작 중 좋은 점수를 받은 작품**을 게재하기도 함

**원고 상태 관리** (이민애 편집장):
- 어드민 상태값: **응모완료 → 검토중 → 미채택/채택**
- 상태값 변경 시 **자동 알림 없음** — 채택 시 **전화**, 응모 완료 시 **문자**로 응모자에게 수동 통보

#### 1-5. 편집

- 편집 도구 및 작업 방식 확인 (완료)

**편집 프로세스** (이민애 편집장):
- 표 입력, 문장 기호(정각 기호 등), 정확한 분량 체크 등을 위해 **한글(HWP)로 편집**
- **정다정 연구소장**: 어드민에 들어온 글의 원본과 윤문(수정) 원고를 **NAS에 다시 업로드**하여 관리

#### 1-6. 순환교정

- 순환교정 방식(프린트 vs 화면) 확인 (완료)

**순환교정 프로세스** (이민애 편집장):
- 한글이나 PDF 파일이 아닌 **직접 인쇄하여 종이로 진행**
- 기자들과 PDF 방식을 협의했으나 **수정 확인 불편, PDF 분배 방법, 지속적 소통 필요성** 등의 이유로 디지털 프로세스 전환이 어렵다는 입장이 주류

**정다정 연구소장**: 눈의 피로, 조작 실수, 순환교정 확인 등을 종합 고려 시 **PC보다 종이 교정이 더 효율적**이라는 판단

#### 1-7. 정산

- 원고료 정산 프로세스 및 소요 시간 확인 (완료)

**원고료 정산 프로세스** (이민애 편집장):
- **엑셀로 수작업** 진행 — 각 담당자가 필자별 원고 매수, 이미지 종류 및 수량 등을 정리하여 수동 비용 산정 후 **WEHAGO에 상신**
- 지난달과 비교하여 **차액 증감 여부 등을 파트별로 전달**하여 정산 진행

## 안건 2. 기 발행 원고 관리 (CMS)

**목표**: CMS에 축적된 33년간 원고의 업로드 프로세스, 검색 실효성, 중복 확인 방식을 파악

### 핵심 질문 요약

| # | 질문 요약 | 검증 대상 |
|---|----------|----------|
| D6 | 3개월마다 잡지 원고 업로드 건수 및 소요 시간 | 수작업 #13 디지털 업로드 정량 |
| D7 | 키워드 검색 정확도 및 미검출 사례 | CMS 검색 기능 실효성 |
| D8 | CMS 등록 원고 총 건수 및 누락 기간 | 디지털 아카이브 규모 + 데이터 이관 범위 |
| D9 | 메타데이터(카테고리·태그·저자) 체계 | CMS 분류 체계 현황 |
| D10 | CMS 외 중복 확인 보완 수단 | CMS 의존도 파악 |

### 인터뷰 결과

#### 2-1. CMS 활용 목적 및 현황

- CMS 접속 → 키워드 검색 → 결과 확인 화면 시연 확인 (완료)
- CMS 활용 용도 확인 (완료)

**CMS 활용 용도** (이민애 편집장):
- **중복 확인 도구**: 원고 채택 과정에서 과거 기사와의 중복 여부를 확인하기 위한 교차 검색. 매월 바뀌는 특집 주제에 걸리지 않도록 CMS에서 **중복 여부 점검**
- **아카이빙 용도**: 발행이 완료된 최종본 업로드
- **월호별 검색** 가능
- 문예대상의 경우 **대상·금상·은상까지만** 업로드
- 궁극적으로 잡지의 **퀄리티를 올리는 목적**으로 운영

#### 2-2. CMS 파일 업로드 및 제약

- 이미지/파일 첨부 용량 제한 확인 (완료)

**파일 업로드 이슈**:
- 이미지/파일 첨부 시 **용량이 제한**되어 있어 업로드에 불편함
- 용량이 큰 파일은 **리사이즈 작업**을 거쳐야 업로드 가능하며, 리사이즈로 인한 **화질 저하 문제** 동반

#### 2-3. 참고도서 관리

- CMS 내 참고도서 관리 기능 확인 (완료)

**참고도서 현황** (이민애 편집장):
- CMS 내 참고도서 현황을 관리하는 기능 존재
- 월마다 기자별로 **5권씩 참고 도서 구매** 가능하며, CMS 등록 도서 현황을 파악하여 **중복 구매 방지**

#### 2-4. CMS 프린트 및 콘텐츠 활용 제약

- CMS 내 프린트 기능 및 콘텐츠 재활용 방식 확인 (완료)

**프린트 기능 부재**:
- CMS에 **프린트 기능이 없어** 콘텐츠 제작·참고·청탁 필자에게 원고 샘플 전송 등의 작업에 불편
- CMS 저장 원고 활용 시 **복사-붙여넣기 방식**으로 수작업 진행

## 안건 3. NAS 활용 현황

> **[참고]** 인터뷰 중 추가 확인
>
> 당초 안건에는 없었으나, 인터뷰 과정에서 NAS가 편집팀 핵심 업무 인프라로 부각되어 별도 항목으로 정리합니다.

### 인터뷰 결과

**NAS 활용 범위** (이민애 편집장):
- 실무자들의 원고 파일 관리는 대부분 **NAS에서 업로드**하여 진행 (PDF, 디자인 파일 등)
- 문예대상 원고글도 업로드. 독자글 중 적절한 글이 없을 때 **동상·장려상 원고를 찾아 게재**하는 데 활용
- 기자들이 원본 및 수정된 원고를 업로드하여 **원고의 변천 과정 확인** 가능

**데이터 백업 및 리스크**:
- 프로덕트 데이터 등 데이터베이스를 **NAS에 백업** 중이나, 부주의로 인한 **데이터 삭제 등 불안 요소** 존재

## 안건 4. 단행본팀 업무 현황

> **[참고]** 인터뷰 중 추가 확인
>
> 당초 안건에는 없었으나, 인터뷰 과정에서 단행본팀의 CMS 미활용 및 타 팀 연계 구조가 확인되어 별도 항목으로 정리합니다.

### 인터뷰 결과

**단행본팀 업무 구조** (이민애 편집장):
- 단행본팀은 **CMS 관련 기능을 거의 활용하지 않으며**, 주로 **계약·출판** 관련 업무 수행
- **프로젝트 단위 운영**: 편집부와 협력하여 완성된 단행본을 인쇄부에 넘긴 후 입고·배분일을 협의하여 배분 날짜 결정
- 이후 영업추진팀에서 주문 건을 처리하고, 정기구독팀은 전자책을 관리
- 프로젝트 당 약 **20~30권**의 단행본 제작

**정다정 연구소장**: 단행본 제작 시 저자 정보 및 계약 정보 확인이 필요하나, 계약서를 확인하기 위해 **시스템에 일일이 찾아 들어가야** 하는 불편함

## 안건 5. 어드민 시스템 현황

### 인터뷰 결과

**어드민 기능 제약** (이민애 편집장):
- 공모전 진행 시 내용을 변경할 때마다 **개발자에게 전달해야 홈페이지 수정 가능**
- 응모 페이지에서 **개별 프린트만 가능**하며, 일괄 프린트 미지원 → 일일이 원고 내용에 들어가서 프린트
- 응모 코너별 독자글, 문예대상 응모글 위주로 데이터 저장

**정주안 테온하우스 대표**: 어드민에서 홈페이지 내용을 변경할 수 있는 기능이 **아예 없어** 새로 코딩하여 페이지를 제작해야 하는 불편함

**어드민-CMS 연동 부재**:
- 어드민(응모 원고)과 CMS(발행 원고)가 연동되지 않아, 채택된 원고를 CMS에 **일일이 복사·붙여넣기**하는 수작업 진행

## 안건 6. 원고 폐기 정책

### 인터뷰 결과

**오프라인 원고** (이민애 편집장):
- 팩스나 우편 등으로 오는 원고는 **디지털화하여 일부 보관**하고 원본은 폐기

**온라인 원고** (이민애 편집장):
- CMS에 저장되지 않은 어드민 내 원고는 **폐기하지 않음** — 좋은생각의 자산으로 보고 그대로 보존 중

**정다정 연구소장**: 어드민 내 원고 데이터는 **휴먼데이터**로서 점차 없어지는 추세이기도 하고 사용 가능성도 있기 때문에 폐기하지 않는 방침

- 디지털 업로드 시 서점별 개별 로그인 필요 여부: 해당 없음 (CMS 단일 접속) (완료)

- 원고료 단가 기준: 필자별 원고 매수, 이미지 종류 및 수량 기반 산정 (완료)

## 인터뷰 결과 요약

### 핵심 발견 사항

1. **어드민-CMS 연동 부재**: 채택된 원고를 CMS에 일일이 복사·붙여넣기하는 수작업 발생. 두 시스템 간 데이터 흐름이 완전히 단절
2. **오프라인 원고 디지털화 미흡**: 약 40박스(박스당 500~600편), 총 7천 편 추정의 오프라인 원고가 어드민/CMS에 저장되지 않은 채 NAS·기자 PC에 산재
3. **메타데이터 부재로 검색 정확도 저하**: CMS 검색 시 주제어로만 검색 가능하며, 메타데이터가 없어 중복 콘텐츠 검증이 불충분
4. **배분 기능의 시스템 부재**: 원고 배분을 수기로 처리하고 있으며, 어드민에서 담당 기자를 지정하는 기능 자체가 없음
5. **프린트 기능 전면 부재**: 어드민에서 일괄 프린트 불가(개별 프린트만), CMS에서는 프린트 기능 자체가 없음
6. **웹사이트 편집 권한 없음**: 공모전 페이지 텍스트·메뉴명 수정에도 개발자에게 하드코딩 요청 필요
7. **체계적 정보 관리 부재**: 저자 정보, 인세 계약 조건, 판권 유효 기간 등을 엑셀·개별 계약서 파일에 의존하여 히스토리 파악 어려움
8. **원고 정보 분산**: 코너별 독자글, 문예대상 입상작, 최종 편집본 등이 어드민·CMS·NAS에 분산 저장
9. **중복 투고 확인의 비효율**: 중복 투고 여부를 제보나 기자의 **직접 전화 확인**에 의존. 실제 중복 투고 사례 발생
10. **NAS 데이터 안정성 우려**: 실무 파일의 핵심 저장소인 NAS에 부주의로 인한 데이터 삭제 리스크 존재

### 신규 발견 수작업·병목

| # | 내용 | 소요 시간 | 담당자 |
|---|------|----------|--------|
