# 킥오프 회의 안건

## 회의 개요

| 항목 | 내용 |
|------|------|
| **회의 목적** | ISP 착수 전, 좋은생각의 실제 업무 프로세스 전체상 파악 및 인터뷰 대상자별 역할 매핑 |
| **일시** | 2026년 2월 23일(월) 또는 24일(화) |
| **참석자** | 정주안 대표 (좋은생각), 김명직 대표·현승인 PM (스컹크웍스스튜디오) |
| **예상 소요** | 1.5~2시간 |

### 회의 배경

인터뷰 대상자가 업무 흐름 중 어떤 구간에 있는지 파악되지 않은 상태에서는 정밀한 인터뷰 설계가 불가능합니다. 따라서 **인터뷰에 앞서** 전체 업무 프로세스와 각 대상자의 역할을 먼저 파악하는 것이 이 회의의 핵심 목적입니다.

:::note[인터뷰 일정 재조율]
기존에 요청한 인터뷰 일정(2/24 CS팀, 2/26 더아이앤오, 3/4 CMS팀)은 **일정을 재조율**합니다. 킥오프 회의 결과를 바탕으로 대상자별 맞춤 질문지를 설계한 후, 인터뷰 일정을 다시 잡을 예정입니다.
:::

---

## 안건 1. 핵심 업무 프로세스 파악

**목표**: CS 시스템 웹 전환의 핵심인 **주문처리**와 **데이터 취합** 프로세스를 단계별로 파악하고, 각 단계의 담당팀·시스템·수작업 구간을 매핑

### 1-1. 주문처리 프로세스 (메인)

주문이 발생해서 고객에게 서비스가 제공되기까지의 **전체 흐름**을 단계별로 파악합니다.

| 단계 | 담당팀 | 사용 시스템 |
|------|--------|-----------|
| ① 주문 발생 (채널별) | 확인 필요 | 확인 필요 |
| ② 주문 수집 | 확인 필요 | 확인 필요 |
| ③ CS 시스템 입력 | 확인 필요 | CS프로그램 |
| ④ 결제 확인 | 확인 필요 | 확인 필요 |
| ⑤ 권한부여/배송 | 확인 필요 | 확인 필요 |
| ⑥ 완료/사후처리 | 확인 필요 | 확인 필요 |

**채널별 차이 확인**:

| 채널 | 수집 경로 | 결제 확인 방식 |
|------|----------|-------------|
| 자사몰(홈페이지) | 확인 필요 | 확인 필요 |
| 외부몰(네이버, 쿠팡 등) | 확인 필요 | 확인 필요 |
| 후원/기타 | 확인 필요 | 확인 필요 |

**핵심 질문**:
- [ ] 채널별로 주문 처리 과정이 다른지? 어디서 갈라지는지?
- [ ] Playauto의 정확한 역할 — 주문 수집만? 결제 확인도?
- [ ] 결제 확인 → 권한 부여까지 실제 소요 시간?
- [ ] 수작업이 발생하는 단계는?
- [ ] 가장 시간이 오래 걸리는 단계는?
- [ ] 담당자 부재 시 멈추는 단계가 있는지?

### 1-2. 데이터 취합 프로세스 (메인)

여러 채널에 흩어진 데이터를 **하나로 모으는 과정** 전체를 파악합니다.

| 단계 | 담당팀 | 사용 도구 |
|------|--------|----------|
| ① 채널별 데이터 수집 | 확인 필요 | 확인 필요 |
| ② 데이터 통합 | 확인 필요 | 확인 필요 |
| ③ CS 시스템 반영 | 확인 필요 | CS프로그램 |
| ④ 검증 | 확인 필요 | 확인 필요 |

**핵심 질문**:
- [ ] 취합 주기는? (일간/주간/월간?)
- [ ] 한 번 취합 시 데이터 양은?
- [ ] 채널별 데이터 형식이 다른지?
- [ ] 통합 시 기준 키(고객ID 등)는 무엇인지?
- [ ] 수작업이 발생하는 단계는?
- [ ] 오류가 자주 발생하는 단계는?

### 1-3. CS(고객서비스) 처리 흐름 (보조)

고객 문의 처리 흐름을 파악하되, **주문처리 프로세스와 연결되는 지점**을 중심으로 확인합니다.

**확인 포인트**:
- [ ] 문의 접수 경로 (전화, 이메일, 기타)
- [ ] 고객 정보 조회 시 사용하는 시스템
- [ ] 주문/결제 관련 문의 처리 시, 주문처리 프로세스의 어느 단계를 참조하는지
- [ ] 내부 CS팀과 외주 콜센터(더아이앤오)의 업무 분담 기준

### 1-4. 문서 기반 추정 검증

아래 내용은 기존 문서에서 **추정한 내용**입니다. 실제와 맞는지 확인이 필요합니다.

| 추정 내용 | 실제? |
|----------|:-----:|
| 주문 수집: Playauto → Excel 다운로드 → CS 프로그램 수동 입력 | ☐ |
| 데이터 취합: 각 채널별 관리자 로그인 → Excel 다운 → 수기 통합 | ☐ |
| 권한 부여: 결제 확인 후 CMS에 별도 접속하여 수동 처리 | ☐ |
| CS 시스템(MSSQL)과 웹 시스템(MySQL)은 완전 분리, 연동 없음 | ☐ |

**추가 파악**:
- 위 추정 외에 **우리가 모르는 수작업 구간**이 있는지?
- 우리가 파악하지 못한 **시스템이나 도구**가 있는지?

## 안건 2. 인터뷰 대상자 역할 매핑

**목표**: 각 인터뷰 대상자가 위 업무 흐름 중 어떤 구간에서 어떤 역할을 하는지 파악

### 대상자별 확인 사항

| 대상자 | 소속팀 | 확인할 것 |
|--------|--------|----------|
| **정황규** | 확인 필요 | 업무 흐름 중 어떤 구간 담당? CS프로그램에서 주로 하는 작업? |
| **어은진** | 확인 필요 | 정황규와 동일 업무? 분담 구조? |
| **더아이앤오 (외주 콜센터)** | 확인 필요 | 좋은생각 CS팀과 어떻게 업무 분담? 콜센터가 처리하는 업무 범위? 사용하는 시스템? |
| **이민애** | 확인 필요 | CMS에서 어떤 작업? 콘텐츠 등록? 관리? 권한부여? |
| **김혜원** | 확인 필요 | 이민애와 동일 업무? 분담 구조? |
| **외주 개발자** | 확인 필요 | CS프로그램 담당? 웹 시스템 담당? 둘 다? 현재 유지보수 범위? |
| **콘텐츠 소장** | 확인 필요 | 정확한 역할? 콘텐츠 제작 흐름에서의 위치? |
| **정용철 대표님** | 확인 필요 | ISP 관련 역할? 인터뷰에서 확인할 주제 (경영 관점)? |

### 역할 매핑 결과 (회의 중 작성)

**주문처리 프로세스 담당팀 매핑**:

```
프로세스 단계                      담당팀              사용 시스템
────────────────────────────────  ──────────────────  ──────────────
① 주문 발생/접수 (채널별)          →                   →
② 주문 수집                       →                   →
③ CS 시스템 입력                   →                   CS프로그램
④ 결제 확인                       →                   →
⑤ 권한부여/배송 처리               →                   →
⑥ 완료/사후처리                   →                   →
```

**데이터 취합 프로세스 담당팀 매핑**:

```
프로세스 단계                      담당팀              사용 도구
────────────────────────────────  ──────────────────  ──────────────
① 채널별 데이터 수집               →                   →
② 데이터 통합                     →                   →
③ CS 시스템 반영                   →                   CS프로그램
④ 검증                           →                   →
```

**CS 처리 담당팀 매핑**:

```
역할                              담당팀
────────────────────────────────  ──────────────────
내부 CS 처리                       →
외주 콜센터 (더아이앤오)             →
시스템 유지보수                    →
경영 의사결정                      →
```

## 안건 3. 기술 환경 확보 요청

### 요청 자료 목록

| 요청 항목 | 상세 | 긴급도 |
|----------|------|:------:|
| **MSSQL DB 접속 정보** | 호스트, 포트, 계정, 비밀번호 | 🔴 높음 |
| **MySQL(CMS/웹) DB 접속 정보** | 동일 | 🔴 높음 |
| **CS 프로그램 접근 방법** | 설치 PC 위치 또는 원격 접근 가능 여부 | 🟠 중간 |
| **외주 개발자 연락처** | 자료 요청 경로 확보 | 🟠 중간 |
| **시스템 구성 관련 자료** | 서버 구성도, 네트워크 구성, 인프라 현황 등 | 🟠 중간 |
| **인원/파트별 업무도표** | 각 담당자·파트별 업무 내역서 또는 R&R 문서 | 🟠 중간 |
| **내부 개선 의견** | 기존에 내부에서 수집된 시스템 개선 관련 의견·건의사항 | 🟡 낮음 |
| **기존 시스템 문서** | 설계서, 매뉴얼, ERD 등 존재 여부 | 🟡 낮음 |

### DB 접근이 필요한 이유 설명

```
DB 접근 → 테이블 구조 파악 → 현행 시스템 정밀진단 (역공학)
                                    ↓
                            AS-IS ERD 작성
                                    ↓
                            TO-BE 설계의 기초 데이터
```

- DB 스키마를 직접 분석해야 현행 시스템의 데이터 구조를 정확히 파악할 수 있음
- 외부 개발자 협조가 제한적인 상황에서, DB 역공학이 핵심 분석 수단

## 안건 4. 인터뷰 일정 재조율

### 공유 사항

1. **기존 요청 일정 재조율**
   - 2/24 CS팀 (정황규, 어은진) → 일정 재조율
   - 2/26 더아이앤오 → 일정 재조율
   - 3/4 CMS팀 (이민애, 김혜원) → 일정 재조율

2. **일정 재조율 사유**
   - 업무 흐름과 대상자 역할을 먼저 파악해야 대상자별 맞춤 질문지 설계 가능
   - 킥오프 회의 결과 반영 후 재설계 → 일정 재요청 예정

3. **향후 일정 조율 방식 합의**
   - 인터뷰 일정 재요청 시 정주안 대표를 통해? 각 대상자에게 직접?
   - 예상 인터뷰 시작 시점: 킥오프 이후 __일 내 (질문지 설계 소요 고려)
