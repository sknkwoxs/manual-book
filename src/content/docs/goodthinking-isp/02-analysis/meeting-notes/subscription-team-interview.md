## 인터뷰 목적

정기구독팀의 **세 가지 핵심 업무 영역**을 파악하고, 각 업무의 현행 프로세스·수작업·병목을 검증합니다.

1. **구독 접수·결제·발송** — 다채널 주문 수집부터 CS System 입력, 결제 확인, 발송 처리까지의 전 과정
2. **CMS 연계 현황 확인** — CMS(콘텐츠 아카이브)와 구독 업무 간 실제 접점 유무 확인, 향후 연계 희망사항 청취
3. **데이터 취합·검증** — 채널별 데이터 통합, 지로/가상계좌 입금 대조, 데이터 정합성 확인

## 안건 1. 구독 접수·결제·발송 프로세스

**목표**: 다채널(전화/웹/외부몰) 구독 접수부터 결제 확인, CS System 입력, 발송 처리까지의 전 과정을 파악하고, 수동 입력·매칭 구간의 시간·건수·오류를 검증

### 핵심 질문 요약

| # | 질문 요약 | 검증 대상 |
|---|----------|----------|

| A3 | CS 처리 시 고객 이력(구독/결제/배송/CS)을 한 화면에서 볼 수 있는지 | 고객 360° 뷰 부재 확인 |
| A4 | 구독 갱신/해지/환불 처리 절차 및 소요 시간 | 구독 라이프사이클 관리 병목 |

## 안건 2. CMS 연계 현황 및 데이터 취합

**목표**: 좋은생각 CMS는 **월간지 발행 콘텐츠를 보관·검색하는 아카이브** 용도이며, CS/구독 정보를 직접 취급하지 않음. 정기구독팀 업무와 CMS 사이에 **실제 접점이 있는지 확인**하고, 향후 연계가 필요하다면 **어떤 영역에서 연결을 원하는지** 청취. 병행하여 채널별 데이터 취합·검증 업무의 실제 소요를 확인

### 핵심 질문 요약

| # | 질문 요약 | 확인 의도 |
|---|----------|----------|
| A2-1 | 현재 정기구독팀 업무에서 CMS에 접속하거나 CMS 데이터를 참조하는 경우가 있는지? 있다면 어떤 상황에서, 얼마나 자주? | CMS ↔ 구독 업무 실제 접점 유무 확인 |
| A2-2 | 구독자에게 CMS 콘텐츠 접근 권한을 부여·회수하는 업무가 실제로 존재하는지? 존재한다면 그 과정은? | 업무 분석에서 추정한 병목 ②, 수작업 #4의 실존 여부 확인 |
| A5 | 향후 웹 전환 시 구독 정보와 CMS(콘텐츠 아카이브)가 연결되면 좋겠다고 생각하는 부분이 있는지? (예: 구독자별 열람 이력, 구독 상태에 따른 콘텐츠 접근 제어 등) | 향후 연계 요구사항 청취 |

### 확인 사항 (인터뷰 중 메모)

**CMS 접점 확인:**
- [ ] 정기구독팀이 CMS에 접속하는 경우: 있음 / 없음
  - 있다면 용도: ___
  - 접속 빈도: 일 ___회 / 주 ___회 / 월 ___회 / 거의 없음
- [ ] 구독자에게 CMS 콘텐츠 접근 권한을 부여하는 업무: 있음 / 없음
  - 있다면 처리 방식: ___
  - 건당 소요 시간: ___분, 월 처리 건수: ___건
- [ ] 구독 만료 시 CMS 관련 처리 업무: 있음 / 없음
  - 있다면 처리 방식: ___
  - 누락 사례: 있음(월 약 ___건) / 없음

**향후 연계 희망사항:**
- [ ] 구독 상태에 따른 콘텐츠 열람 제어 필요: 예 / 아니오
- [ ] 구독자별 콘텐츠 열람 이력 추적 필요: 예 / 아니오
- [ ] CMS와 연계되었으면 하는 기타 요구사항: ___

**데이터 취합·검증:**
- [ ] 채널별(자사몰/외부몰/후원) 데이터 취합 방식 차이 확인
- [ ] 지로 입금 대조 시 참조하는 화면/파일: ___
- [ ] 데이터 검증(목시 확인) 항목: ___ / 주기: ___
