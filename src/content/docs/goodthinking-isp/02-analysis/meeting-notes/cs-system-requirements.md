# 기능요건 — CS 시스템

:::note[문서 기준]
본 문서는 4개 부서 인터뷰에서 도출한 **CS 시스템 관련 기능요건 25건**을 통합 정리한 것입니다. 부서간 중복 기능요건 6쌍을 통합하여 31건 → 25건으로 정리하였습니다.
소스 인터뷰: [정기구독팀](/goodthinking-isp/02-analysis/meeting-notes/subscription-team-interview/) · [콜센터](/goodthinking-isp/02-analysis/meeting-notes/call-center-interview/) · [경영지원팀](/goodthinking-isp/02-analysis/meeting-notes/management-support-team-interview/) · [영업추진팀](/goodthinking-isp/02-analysis/meeting-notes/sales-team-interview/)
:::

:::note[중점 논의 사항]
엑셀 추출 자동화는 좋은생각의 여러 부서가 공통으로 겪고 있는 '반복적인 수작업'을 해결하기 위한 핵심 기능요건으로, 다음과 같은 내용이 논의되었습니다.
- **사용자 정의 양식 설정**: 고정된 양식뿐만 아니라, 사용자가 직접 필요한 데이터 항목을 선택하고 매칭하여 새로운 엑셀 시트 양식을 만들 수 있는 기능을 요구하고 있습니다.
- **데이터 연산 추출**: 요구사항 정리 회의 중 단순한 DB 값 추출을 넘어, A열과 B열의 데이터를 연산(예: 수량 × 단가 = 매출액)한 결과값을 엑셀 시트에 바로 삽입해 주는 확장된 기능까지 논의되었습니다.
- **일괄 업로드 및 오류 보정**: 엑셀을 업로드할 때 콤마(,)나 띄어쓰기 오류로 인해 전체 업로드가 중단되는 현재의 불편함을 개선하여, 오류가 있는 데이터만 골라내어 시스템 상에서 수정 후 업로드할 수 있는 '보정 기능'이 제안되었습니다.

본 문서 내 [SUB-008 엑셀 양식 표준화 및 일괄 업로드 개선](#sub-008), [MGT-001 엑셀 서식 표준화 및 자동 변환](#mgt-001), [MGT-004 선수수익 현황표 양식 표준화](#mgt-004) 등 다수의 기능요건이 이 문제를 다루고 있습니다.
:::

## 기능요건 상세 — 정기구독팀 (SUB)

### SUB-001

| 항목 | 내용 |
|------|------|
| **번호** | SUB-001 |
| **제목** | 개인정보 자동 파기 |
| **내용** | 개인정보 보유 기간 경과 또는 처리 목적 달성 시, 해당 고객 정보를 **자동으로 휴면처리·재동의 요청·마스킹 처리**하는 기능을 구현한다. 파기 대상 목록 자동 추출, 파기 이력 관리(일시·항목·처리자), 파기 전 알림 및 재동의 프로세스를 포함한다. |
| **배경** | 현재 5년 경과 개인정보의 자동 삭제 기능이 없어, 정황규 매니저가 매월 과거 만료자를 엑셀로 추출하여 **일일이 눈으로 대조하며 삭제**하는 수작업을 진행 중. 정기구독팀 인터뷰에서 **"가장 급한 법적 리스크"**로 직접 언급되었으며, 개인정보보호법상 보유 기간 경과 시 지체 없이 파기해야 하나 수동 처리 방식은 누락 위험이 높음. ([R1](/goodthinking-isp/02-analysis/meeting-notes/subscription-team-interview/#시스템-기능-개선-요구사항), [N4](/goodthinking-isp/02-analysis/meeting-notes/subscription-team-interview/#신규-발견-수작업병목)) |
| **관련 시스템** | CS 시스템 |
| **관련 메뉴** | 관리자업무 > 회원 현황 |
| **관련 부서** | 정기구독팀, 경영지원팀 |

:::caution[법적 리스크]
개인정보보호법상 보유 기간 경과 시 지체 없이 파기해야 하며, 현재 수동 처리 방식은 누락 위험이 높아 **최우선 구현 대상**입니다.
:::

### SUB-002

| 항목 | 내용 |
|------|------|
| **번호** | SUB-002 |
| **제목** | 재고 연동 |
| **내용** | 위하고/CS 시스템/물류 창고 간 **재고 수치를 확인**하는 기능을 구현한다. 불일치 발생 시 알림, 이력 추적 기능을 포함한다. 구독선물재고관리 메뉴에서 수정이 가능해야 한다. **단행본 재고**도 고려출판물류 시스템과 연동하여 전 직원이 재고를 쉽게 공유할 수 있는 대시보드를 제공한다. |
| **배경** | 물류 창고에서 15일 단위로 전달받는 엑셀 재고와 위하고/CS 시스템 수량이 서로 맞지 않아 매월 말 **임의로 수치를 조정해 강제로 끼워 맞추고 있음**. 오차 원인 파악이 어려움. 단행본 재고량 확인 및 증쇄/절판 여부 판단은 모두 개인 엑셀 파일로 작업하며, 정기구독팀과 재고 공유 시에도 별도 조회 필요. 편집팀의 신간/단행본 인쇄 완료 시점을 시스템으로 알 수 없어 출고 스케줄 수립에 어려움. ([R3 정기구독팀](/goodthinking-isp/02-analysis/meeting-notes/subscription-team-interview/#시스템-기능-개선-요구사항), [N5](/goodthinking-isp/02-analysis/meeting-notes/subscription-team-interview/#신규-발견-수작업병목), [핵심 발견 #6 영업추진팀](/goodthinking-isp/02-analysis/meeting-notes/sales-team-interview/#핵심-발견-사항), [N7](/goodthinking-isp/02-analysis/meeting-notes/sales-team-interview/#신규-발견-수작업병목)) |
| **관련 시스템** | CS 시스템, 위하고(WEHAGO), 물류 창고 시스템, 고려출판물류 |
| **관련 메뉴** | 발송업무 > 구독선물재고관리, 재고수불부관리 |
| **관련 부서** | 정기구독팀, 경영지원팀, 영업추진팀, 편집팀 |

:::note[논의 사항]
- **CS 시스템 내 재고 관리 회의론**: 위하고(WEHAGO)가 결제 및 자산 관리 모듈을 가지고 있으므로, 재고 정보는 CS 시스템이 아닌 위하고를 중심으로 관리하는 것이 맞다는 의견이 제시되었습니다.
- **엑셀 기반의 간접 연동**: 물리적인 API 통합 대신, 물류 창고에서 받은 엑셀 서식을 CS 시스템에 쉽게 업로드하여 최신 재고 상태를 업데이트하는 '업무 효율화' 방식이 핵심 대안으로 꼽혔습니다.
- **단행본 제외**: 재고 연동 범위에서 업무 플로우가 완전히 다른 '단행본'은 제외하고, 우선 '좋은생각' 잡지와 관련된 재고에만 집중하기로 했습니다.
:::

- **장기적 로드맵**: 향후 단행본 사업 규모가 커지면 CMS에서 다루거나 단행본 전용 시스템을 별도로 개발하는 것이 맞다는 방향을 설정했습니다.
:::
