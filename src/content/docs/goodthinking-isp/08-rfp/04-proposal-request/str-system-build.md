## 시스템 구축 요구사항 (STR) 개요

시스템 구축 요구사항(STR, System Technical Requirements)은 좋은생각 CS 시스템 웹 전환 사업의 기술적 기반을 정의하는 요구사항 분류임. 본 분류는 아키텍처 설계, 인프라 구성, 플랫폼·프레임워크 선정, 외부 시스템 통합·연동 패턴, 데이터베이스 설계, 화면·UI 설계, 운영·관제 설계 등 7개 영역으로 구성됨.

제안사는 각 요구사항에 대해 ISP 단계에서 도출한 권고안을 기반으로 동등 이상의 대안을 제시할 수 있으며, 평가는 제품명이 아니라 **달성 목표 충족 여부와 합리적 근거**로 진행함. 특정 제품·인프라 강제 없음.

---

## STR 상세 요구사항

| 요구사항 분류 | 요구사항 고유번호 | 요구사항 상세설명 | 산출정보 |
|:---:|:---:|---|---|
| 아키텍처 설계 | STR-001 | **(1) 목표**<br>가용성·확장성·보안 목표를 만족하는 전체 아키텍처(환경 분리, 모듈 경계, 연동 패턴) 제시<br><br>**(2) 세부 내용**<br>- 운영/스테이징/개발 3환경 분리 및 배포·롤백 전략 명시<br>- 모듈형 모놀리식(또는 제안 대안) 아키텍처와 도메인별 책임 정의(고객·구독·주문·결제·CS 등 10개 파트)<br>- 인프라 형태(클라우드/온프레미스/컨테이너) 선택 근거 및 비용·운영 영향 분석<br>- CI/CD 파이프라인 구성(빌드→테스트→배포)과 자동화 단계 정의<br>- DB 고가용성(동기 복제·Failover) 방안 제시 | - 시스템 아키텍처 설계서 (PDF)<br>- 환경 구성도(운영/스테이징/개발) 다이어그램<br>- 배포·롤백 절차서<br>- CI/CD 파이프라인 구성도 |
| 인프라 구성 | STR-002 | **(1) 목표**<br>웹 방화벽·CDN·HTTPS 강제 등 운영·보안 요건을 만족하는 인프라 구성 보장<br><br>**(2) 세부 내용**<br>- 웹 방화벽(WAF) + CDN 계층 설계 및 OWASP Top 10 방어 룰 적용<br>- TLS 1.3 강제 적용 및 공인 인증서 갱신 자동화<br>- 모니터링·알람(메트릭·로그·에러 추적) 도구 연동 지점 정의<br>- 네트워크 분리(인터넷·DMZ·내부망) 및 VPN(외부 콜센터) 접속 정책<br>- 확장성(Auto-scaling 또는 수동 증설) 절차 명시 | - 인프라 구성도 및 네트워크 다이어그램<br>- 모니터링·알람 적용 목록 및 룰셋<br>- TLS 인증서 관리 절차서<br>- VPN 접속 정책서 |
| 플랫폼·프레임워크 | STR-003 | **(1) 목표**<br>프론트엔드·백엔드·DB·캐시·검색 등 권고 스택을 채택하거나 동등한 대안의 타당성 제시<br><br>**(2) 세부 내용**<br>- 프론트엔드: SPA(예: React/Vue) + 컴포넌트 라이브러리 권고<br>- 백엔드: 모듈화 가능한 프레임워크(예: NestJS/Spring/Django) 및 API 표준(OpenAPI 3.0)<br>- DB: 현행 MSSQL 유지 또는 동등 성능의 대안 제시(이관 리스크 분석 포함)<br>- 캐시: 인메모리 캐시(예: Redis) 또는 등가 솔루션<br>- 대안 채택 시 라이선스·운영 비용·인력 확보 가능성 비교 분석 첨부 | - 기술 스택 표 (분류·제품명·버전·라이선스)<br>- 권고 vs 대안 비교 분석서<br>- OpenAPI 3.0 스펙 샘플<br>- 라이선스 검토서 |
| 통합·연동 패턴 | STR-004 | **(1) 목표**<br>Playauto, PG(나이스페이), ERP(WEHAGO), 택배사, CMS 등 외부 시스템과 안정적·확장 가능한 연동 보장<br><br>**(2) 세부 내용**<br>- 어댑터 패턴 채택으로 신규 채널 추가 시 기존 코드 수정 최소화<br>- 연동별 신뢰성 정책(재시도·큐잉·Circuit Breaker) 명시<br>- 동기/비동기 처리 분리(예: PG 결제는 동기, 외부몰 주문 동기화는 비동기 폴링·Webhook)<br>- Webhook/폴링 주기 명시(예: Playauto 5분 폴링) 및 실패 시 백업 프로세스<br>- 연동 모니터링(성공률·지연시간·실패 알람) 대시보드 제공 | - 연동 매트릭스 (외부 시스템·연동 방식·주기·SLA)<br>- 어댑터 인터페이스 명세서 (OpenAPI)<br>- 장애 시 처리 플로우 다이어그램<br>- 연동 모니터링 대시보드 스냅샷 |
| 데이터베이스 설계 | STR-005 | **(1) 목표**<br>현행 분산 DB(CS·홈페이지·CMS — 약 151테이블)를 통합한 TO-BE DB 설계(ERD) 제공<br><br>**(2) 세부 내용**<br>- 핵심 엔티티(고객·구독·주문·결제·CS·발송 등) 정의<br>- 마이그레이션 고려한 PK/인덱스·파티셔닝·아카이빙 정책<br>- 감사 로그·개인정보 암호화 필드 명세<br>- 성능 목표(응답시간·동시접속) 충족을 위한 쿼리 튜닝 가이드 포함 | - ERD (PNG/SVG)<br>- DDL 스크립트<br>- 인덱스·쿼리 튜닝 가이드<br>- 데이터 보존·아카이빙 정책 문서 |
| 화면·UI 설계 | STR-006 | **(1) 목표**<br>현행 86개 화면 기준 SPA 컴포넌트·재사용성·반응형 설계 제공<br><br>**(2) 세부 내용**<br>- 주요 화면 우선순위 정의(13개 핵심 화면 1차 개발)<br>- 컴포넌트 라이브러리 기준 설계와 상태관리 권고<br>- 접근성·크로스브라우징 기본 규칙 적용(Chrome/Edge/Safari 최신 2개 버전)<br>- 반응형 지원(데스크톱 1280px+, 태블릿 768px+)<br>- Figma 등 디자인 도구 핸드오프 산출물 제공 | - 화면 설계서(Wireframe, Figma 링크 또는 PNG)<br>- 컴포넌트 목록 및 사용 가이드<br>- UI/UX 핸드오프 산출물 (PDF)<br>- 반응형 검증 체크리스트 |
| 운영·관제 설계 | STR-007 | **(1) 목표**<br>운영 개시 후 가용성·백업·모니터링·복구 절차가 명확한 운영 체계 수립<br><br>**(2) 세부 내용**<br>- 가용성 목표(예: 99.5%)와 장애 등급별 SLA(응답·복구 시간) 정의<br>- 백업 정책(일별 스냅샷, 보관 기간 30일 권장) 및 복구 절차<br>- 모니터링 항목(응답시간·에러율·디스크·DB 지연) 및 알람 임계값<br>- 운영 인력 R&R(1차/2차 대응) 및 에스컬레이션 절차 | - 운영 가이드(운영절차·SLA) PDF<br>- 모니터링 대시보드 스냅샷<br>- 백업·복구 검증 리포트<br>- 장애 대응 Runbook |
