# 제4장 제안 요청 사항

본 4장은 좋은생각 CS 시스템 웹 전환 사업의 모든 요구사항을 7개 분류로 체계화하여 제시합니다. 제안사는 각 요구사항에 대한 구현 방안, 기술 스택, 일정 계획을 제안서에 포함해야 합니다.

## 4.1 제안 요청 개요

### 본 장의 구성

제4장은 다음과 같이 구성됩니다:

- **4.1 제안 요청 개요**: 본 장의 구성 및 요구사항 분류 체계 설명
- **4.2 목표 시스템 구성도**: 전체 시스템 아키텍처 및 외부 연동 구성
- **4.3 상세 요구 사항**: 7개 분류별 상세 요구사항 목록

### 요구사항 분류 체계

전체 요구사항은 다음 7개 분류로 구분됩니다:

| 분류 코드 | 분류명 | 설명 |
|----------|--------|------|
| **STR** | 시스템 구축 요구사항 | 인프라, 아키텍처, 개발환경 구축 관련 |
| **SRE** | 기능 요구사항 | 사용자/관리자 기능, 업무 프로세스 구현 |
| **SER** | 보안 요구사항 | 인증, 권한, 암호화, 보안 정책 |
| **DAR** | 데이터 요구사항 | 데이터 이관, 백업, 정합성 관리 |
| **TER** | 테스트·운영 요구사항 | 테스트 계획, 운영 이관, 모니터링 |
| **EDR** | 교육·기술지원 요구사항 | 사용자 교육, 매뉴얼, 기술 이전 |
| **COR** | 제약사항 | 준수해야 할 기술적·정책적 제약 조건 |

### 총 요구사항 건수

전체 요구사항은 **91건**으로 구성됩니다:

- **STR** (시스템 구축): 7건
- **SRE** (기능): 56건
- **SER** (보안): 6건
- **DAR** (데이터): 6건
- **TER** (테스트·운영): 6건
- **EDR** (교육·기술지원): 5건
- **COR** (제약사항): 5건

## 4.2 목표 시스템 구성도

### 전체 시스템 아키텍처

![전체 시스템 아키텍처 구성도](/diagrams/08-rfp/system-architecture.svg)


### 주요 구성 요소

#### 프론트엔드 계층
- **웹 SPA**: 사용자용 단일 페이지 애플리케이션 (Vue.js 또는 React 기반)
- **관리자 웹**: CS 관리자 및 시스템 관리자용 관리 콘솔

#### 백엔드 계층
- **API Gateway**: RESTful API 또는 GraphQL 엔드포인트 제공
- **인증·권한 서비스**: JWT 기반 인증, 역할 기반 접근 제어(RBAC)
- **비즈니스 로직 서비스**: 주문, 회원, 상품, CS 등 핵심 업무 로직

#### 데이터 계층
- **메인 DB**: MySQL 또는 PostgreSQL 기반 관계형 데이터베이스
- **캐시**: Redis 기반 세션 및 데이터 캐싱
- **파일 스토리지**: S3 또는 NAS 기반 파일 저장소

#### 외부 연동 시스템 (6개)
1. **나이스페이 (PG)**: 신용카드, 계좌이체 등 결제 처리
2. **Playauto (외부몰)**: 외부 쇼핑몰 주문 연동
3. **CMS (콘텐츠 관리)**: 상품 정보, 이미지, 설명 관리
4. **위하고 (ERP)**: 재고, 출고, 회계 연동
5. **CTI (전화 상담)**: 고객 상담 전화 시스템 연동
6. **택배사**: 배송 조회 및 송장 출력 연동

### 요구사항 표 형식 안내

각 분류별 상세 페이지에서는 다음 형식의 표로 요구사항을 제시합니다:

- **요구사항 분류**: 해당 요구사항이 속한 분류 코드 (예: STR, SRE)
- **요구사항 고유번호**: 분류 코드 + 일련번호 (예: STR-001, SRE-001)
- **요구사항 상세설명**: 구현해야 할 기능 또는 충족해야 할 조건의 구체적 설명
- **산출정보**: 해당 요구사항 이행 시 제출해야 할 산출물 (예: 설계서, 소스코드, 테스트 결과서)

제안사는 각 요구사항에 대해 **이행 방안**, **적용 기술**, **일정 계획**을 제안서에 명시해야 하며, 요구사항 미이행 시 사유를 반드시 기재해야 합니다.
