## A. 요구기능정의서

### A.1. 식별자 체계 안내

- 본 사업 요구사항은 다음 ID 규칙을 따름
- 제안사는 본 식별자를 기준으로 제안서 내 구현 방안을 매핑하여 작성

| 구분 | 형식 | 예시 |
|------|------|------|
| 기능 요구사항 | `{파트코드}-{일련번호}` | DB-01, CM-05, FN-16 |
| 비기능 요구사항 | `{카테고리}-{일련번호}` | PF-01, SC-05, AV-03, CP-02 |

**파트 코드 매핑**: DB(대시보드) · CM(고객 관리) · SB(구독 관리) · OM(주문 관리) · DL(배송 관리) · FN(결제/정산) · CS(CS/상담) · GF(선물 관리) · BK(재고/도서) · AD(시스템 관리) · PF(성능) · SC(보안) · AV(가용성) · CP(호환성).

**우선순위 분류**: 필수(Must Have) · 높음(Should Have) · 중간(Nice to Have) · 권장 · 선택.

**현행지원 표기**: 지원 / 부분 지원 / 미지원 / 미작동 — `[현행 존치]`는 안정 운영 중인 기능으로 웹 전환 시 동등 기능 보장 필수.
