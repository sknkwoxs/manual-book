# 3. 제안 요청 내용

## 3.1. 기술 제안

- 제안사가 다음 항목에 대해 구체적 수행 방안을 제시할 것
- 본 절에 기술된 기술 스택·아키텍처·프로세스·이관 방안은 ISP 단계에서 도출한 권고안임
- 이를 기반으로 동등 이상의 대안 제시 가능

### 3.1.1. 사업 이해 및 접근 방법

> **이 절의 목표:** 제안사가 좋은생각의 사업 도메인·규모·복잡도를 정확히 이해하고 있는지 확인.

- 본 사업의 배경·목적·범위에 대한 이해
  - 33년 누적 C/S(XPlatform) 기반 폐쇄형 시스템을 웹 기반 통합 관리자 시스템으로 전환
  - 외부콜센터(더아이앤오) CTI 중단, CMS 권한 수동 복사, ERP(위하고) 이중 입력 등 일일 6.5\~9시간 수작업 해소
  - 자사몰·외부몰(네이버/쿠팡 — Playauto 경유)·CMS·ERP·PG(나이스페이)·CJ대한통운/우체국 연동 일원화
- 사업 추진 전략 및 차별화 방안 제시
- 핵심 성공 요인(CSF) 및 주요 리스크 식별·대응 방안 제시
- 사용자 규모·데이터 규모에 대한 이해
  - 동시 사용자 약 10\~15명 (사내 직원 \~10명 + 외부콜센터 4명)
  - 통합 DB 약 138 테이블 규모 (고객관리 75 + 홈페이지 63), 누적 데이터 합산 약 50\~150만 건
  - 기존 비즈니스 로직 49건 (저장 프로시저 20 + 함수 14 + 트리거 15)

### 3.1.2. 시스템 아키텍처

> **이 절의 목표:** 제안 아키텍처가 가용성·확장성·보안 목표를 어떻게 달성하는지 확인.

#### 권장 기술 스택

> **본 표는 ISP 단계의 권고이며, 특정 제품·프레임워크 강제가 아님.**
> 제안사는 동등 이상의 기술로 자유롭게 대안을 제시할 수 있으며, 평가는 제품명이 아니라 **달성 목표 충족 여부와 합리적 근거**로 진행함.

| 계층 | 구분 | 권고 요건 (목표) | 참고 예시 |
|------|------|------------------|-----------|

#### 주요 아키텍처 결정 사항 (Tradeoff)

| 항목 | 권고 방향(예시) | 근거 |
|------|------------------|------|
| 현행 RDBMS 유지 vs 타 엔진 전환 | 현행 RDBMS 엔진 유지(이관 리스크 최소화) | 데이터 이관 부담 경감, 기존 49건 로직 재활용 가능 |
| 모놀리식 vs MSA | 모듈형 모놀리식 | 15명 규모, 단일 팀 운영에 적합 |
| 관리형 컨테이너 vs Kubernetes | 관리형 컨테이너 서비스(K8s 대비 운영 단순화) | 운영 복잡도 대비 비용 효율 우수 |
| 자체 인프라 vs 클라우드 전면 이전 | 클라우드 기반 인프라(현행 VPN 보안 취약점 해소) | 온프레미스 유지 비용 대비 경제성, 보안 강화 |

> 구체 제품 선택은 제안사 권한이며, 위 권고 방향과 동등한 효과를 입증하면 채택 가능함.

### 3.1.3. 기능 구현 방안

> **이 절의 목표:** 79건 기능 요구사항을 어떤 구조로 구현할 계획인지 확인.

#### 핵심 엔티티 (TO-BE 통합 DB)

- 기존 분산 구조(고객관리 DB + 홈페이지 DB)를 단일 통합 DB로 일원화
- 핵심 엔티티 및 비즈니스 의미는 다음과 같음

| 엔티티 | 주요 컬럼 | 비고 |
|--------|----------|------|
| 고객(Customer) | 고객코드(고유), 이름, 전화번호, 이메일, 등급, 주거래채널 | 현행 고객 마스터를 정규화 통합 (약 48개 필드) |
| 구독(Subscription) | 고객(외래), 상품유형, 구독시작일, 구독종료일, 상태, 채널 | 현행 구독 + 정기주문 정보 통합 |
| 주문(Order) | 주문코드(고유), 고객(외래), 채널, 총금액, 결제상태, 배송상태, 외부 주문ID | 자사몰·외부몰·전화 주문 통합 |
| 결제(Payment) | 주문(외래), 결제수단, 금액, 결제일자 | 현행 재무 거래(입금/환불) 분리 |
| 배송(Delivery) | 주문(외래), 배송사, 송장번호, 상태 | 우체국·CJ대한통운 통합 |
| 상담(CS Tickets/Histories) | 고객(외래), 유형, 상태 | 현행 상담 이력 분리 |
| 선물/재고(Gift/Stock) | 상품(외래), 수량 | 현행 선물재고 + 재고 통합 |
| 감사 로그(Audit Log) | 수행자, 동작, 대상 자원, 변경 전 값, 변경 후 값, IP 주소 | 전 기능 변경 이력 |

### 3.1.4. 데이터 통합 및 이관 방안

> **이 절의 목표:** 분산 데이터를 무중단·무손실로 통합·이관할 수 있는 계획인지 확인.

#### 외부 시스템 연동 매트릭스

| 외부 시스템 | 연동 방식 | 방향 | 주요 데이터 |
|-------------|----------|------|-------------|
| 자사몰 (홈페이지) | 통합 DB 직접 (단일 DB) | 양방향 | 회원, 주문, 상품 |
| 네이버 스마트스토어 | Playauto API 폴링 (5분) | 수신 | 주문 |
| 쿠팡 | Playauto API 폴링 (5분) | 수신 | 주문 |
| 좋은생각 CMS | Excel 파일 (수동 업/다운) | 송신 | 구독자 열람 권한 명단 |
| 위하고(WEHAGO) ERP | Excel 파일 (수동 업로드) | 송신 | 매출 전표, 세금계산서 |
| 나이스페이 PG | Webhook + REST API | 양방향 | 결제 승인/취소/환불 |
| CJ대한통운 | REST API | 양방향 | 송장 등록, 배송 추적 |
| 우체국 | REST API | 양방향 | 송장 등록, 배송 추적 |
| SMS/알림톡 | 외부 SMS 사업자 API | 송신 | 발송 알림, 만료 안내 |
| 이메일 | SMTP / 외부 이메일 사업자 | 송신 | 안내, 영수증 |
| CTI (LG U+) | 웹 CTI 팝업 연동 | 수신 | 발신번호 |

> **CMS 연동 정책**: 좋은생각 CMS는 월간지 원고 아카이브 시스템으로, 데이터 통합 대상이 아닙니다. CMS와의 유일한 접점은 구독자 열람 권한 대상 목록 Excel 전달입니다.
>
> **ERP 연동 정책**: 위하고(WEHAGO)가 외부 API를 제공하지 않아 Excel 자동 생성을 통한 업로드 방식을 채택합니다.

#### 정합성 검증

- **건수 검증**: 테이블별 AS-IS / TO-BE 건수 비교, 차이 0 (중복 통합으로 감소 시 별도 기록)
- **합계 검증**: 결제 금액·구독 건수 등 핵심 지표 합계 일치
- **샘플 검증**: 무작위 100건 추출 1:1 필드 대조
- **롤백 트리거**: 정합성 90% 미만, 주요 기능 오류, 성능 기준 미달 시 즉시 롤백
- **롤백 절차**: 신규 시스템 차단 → 기존 시스템 재활성화 → Delta 역이관 → 원인 분석

#### 주요 필드 변환 규칙

| AS-IS | TO-BE | 변환 규칙 |
|-------|-------|----------|
| 고객ID (decimal 13) | 고객코드 (VARCHAR) | 문자열 변환, 앞 0 패딩 |
| 전화번호 / 휴대전화 | 전화번호 / 휴대전화 | 숫자만 추출 (11자리 정규화) |
| 이메일 | 이메일 | 소문자 변환, 유효성 검증 |
| 구독시작일 | 구독시작일 | UTC 변환 |
| 고객유형 코드 | 고객유형 | 코드 매핑 (`01`→individual, `02`→corporate, `03`→school) |

- 정기 업데이트 및 보안 패치 정책 제시

## 3.4. 산출물 요구사항

> **이 절의 목표:** 단계별 산출물의 명확한 정의와 인수인계 가능성 확인.

- 제안사는 사업 수행 과정에서 다음 산출물을 발주처에 납품할 것

| 단계 | 주요 산출물 |
|------|-----------|
| 분석 | 요구사항 분석서, 현행 시스템 분석서, ISP 산출물 검토 의견서 |
| 설계 | 시스템 아키텍처 설계서, 데이터베이스 설계서(ERD 포함), 화면 설계서(Wireframe), 인터페이스 설계서, API 명세서(OpenAPI/Swagger) |
| 개발 | 소스 코드 (형상 관리 저장소), 빌드/배포 스크립트, 단위 테스트 결과서 |
| 테스트 | 통합 테스트 결과서, 시스템 테스트 결과서, 성능 테스트 결과서, 보안 점검 결과서, UAT 결과서 |
| 이관 | 데이터 이관 계획서, ETL 스크립트, 매핑 정의서, 이관 결과 검증 보고서 (건수·합계·샘플 100건), 롤백 계획서 |
| 운영 | 사용자 매뉴얼, 운영자 매뉴얼, 관리자 매뉴얼, 운영 환경 구성도, 모니터링 대시보드 가이드 |
| 종료 | 사업 완료 보고서, 검수 확인서, 인수인계서, 교육 결과 보고서 |
