# 2. 현황 및 요구사항

본 장은 좋은생각의 현행 시스템·업무 현황과 본 사업에서 구현해야 할 **기능 79건 + 비기능 14건 = 총 93건**의 요구사항, 데이터 이관 및 외부 연동 요구사항을 정의. 본 장의 내용은 ISP 1단계 산출물(현황 분석, 요구사항 정의서, 품질 속성 시나리오, 마이그레이션 계획)의 통합·요약본이며, 모든 요구사항은 본 RFP 본문에 자기완결적으로 기재됨.

## 2.1. 현행 시스템 현황

### 2.1.1. 현행 시스템 개요

좋은생각의 정기구독·콘텐츠 운영을 지원하는 현행 시스템 구성은 다음과 같음.

| 시스템 | 역할 | 기술 스택 | 위치 / 비고 |
|--------|------|-----------|------------|
| CS 시스템 (고객관리 프로그램) | 고객·구독·주문·결제·발송·CS 운영 | Tobesoft XPlatform 9.2.1 + Java(eGovFrame 3.2), Tomcat 7.0, ActiveX 기반 (Windows/IE 전용) | `cs.positive.co.kr` (203.231.234.6, Windows Server 2012). **본 사업의 주요 전환 대상** |
| CS DB 서버 | CS 시스템 데이터 저장 | MSSQL Server 2008 | `203.231.234.7:1433`. 75 테이블 + 20 SP + 14 Function + 15 Trigger |
| 자사 홈페이지 | 정기구독 신청·결제·콘텐츠 제공 | SPA (Single Page Application) | AWS. 데이터 연동 대상 |
| CMS (좋은생각 CMS) | 월간지 콘텐츠 아카이브, 회원 권한 관리 | 웹 | AWS. 13 테이블. 권한 부여 자동화 대상 |
| Admin (홈페이지 관리) | 회원·주문 관리 웹사이트 | Node.js | AWS. 63 테이블 + 7 SP |
| ERP — 위하고(WEHAGO) | 매출·정산·세금계산서 | 외부 SaaS | 현재 엑셀 양방향. API 연동 대상 |
| PG — 나이스페이 | 신용카드/ARS/가상계좌/현금영수증 | 외부 SaaS, 4~5개 계정 운영 | API 연동 대상 |
| 외부몰 수집 — Playauto | 네이버/쿠팡 등 외부몰 주문 수집 | 외부 솔루션 | 현재 엑셀 수동 다운로드. 자동화 대상 |
| 금융결제원 | 지로 입금 파일(`ocrser.txt`) 수령 | 파일 업로드 | 일 1회 |
| 외부 콜센터 — 더아이앤오 | 아웃바운드 콜 (약 4명) | - | CS 접수 데이터 공유 |

CS 시스템 화면은 사용자 매뉴얼 74개 + 관리자 매뉴얼 12개 = **총 86개 화면**으로 구성되며, 업무 영역별로 BS(기본/관리자) 12, SS(접수) 11, DP(입금) 11, MP(발송/리포트) 48, SD(영업) 2, 추가프로그램 2개로 분포. DB 비즈니스 로직은 CS DB(20 SP + 14 Function + 15 Trigger = 49건)와 홈페이지 DB(7 SP)를 합쳐 **총 56건** 식별. 본 사업에서 서비스 레이어로 재구현해야 할 핵심 전환 대상.

### 2.1.2. 현행 시스템의 주요 한계

| 영역 | 한계 | 심각도 |
|------|------|:----:|

| 기술 EOL | MSSQL Server 2008(2019.7 지원 종료), Windows Server 2012(2023.10 지원 종료) — 보안 패치 중단 | Critical |

| 비즈니스 로직 분산 | 56건 비즈니스 로직이 DB SP/Function/Trigger에 내장 — 단위테스트·버전관리 불가 | High |

| 문서화 부재 | API 명세·DB 스키마 문서 없음 | Medium |

### 2.1.3. 현행 업무 흐름 및 수작업 현황

화면 시연 인터뷰(정기구독팀, 영업추진팀, 경영지원팀, 편집팀, 외주콜센터 + CEO) 결과 식별된 주요 수작업은 **총 58건**, 일일 평균 7~10시간(CS·판매·정산 3개 팀 기준, 정기구독팀·경영지원팀 실측 포함) 소요. 대표적 병목 구간은 다음과 같음.

| 병목 | 원인 | 영향 |
|------|------|------|
| 주문 수집 → CS 입력 | Playauto/홈페이지 ↔ CS API 미연동, 수동 Excel 가공·등록 | 일 25~60건, 매일 오전 3~4시간 일괄 배치 |
| 결제 확인 → CMS 권한 부여 | CS(On-Prem) ↔ CMS(AWS) 완전 분리 | 결제 후 콘텐츠 이용 지연 수시간~1영업일 |

| CTI 미작동 | KT→LG 회선 전환 후 서울정보시스템 CTI 팝업 중단 | 콜센터 전화번호 수동 검색 |

| 개인정보 수동 파기 | 5년 경과자 자동 파기 기능 부재 | 개인정보보호법 위반 리스크(법적 제재) |

### 2.2.1. 대시보드 (DB) — 5건

> **이 파트의 비즈니스 목표**
>
> - **해결할 페인포인트**: 매출·구독·CS 데이터를 매일 30~60분간 수기 취합, 임원·팀장이 현황 파악까지 반나절 소요
> - **달성 목표(KPI)**: 통합 대시보드 자동 집계, 임원이 매일 아침 5분 내 핵심 지표 파악, 일일실적관리보고서 작성 시간 80% 단축
> - **주요 사용자**: 임원, 정기구독팀장, 영업추진팀장, 경영지원팀장

| ID | 요구사항명 | 설명 | 우선순위 / 현행 |
|----|-----------|------|----------------|
| DB-01 | 준실시간 KPI 대시보드 | 당일 매출·신규 구독자·주문 현황 등 핵심 운영 지표를 5분 주기 갱신·시각화 제공. 임원·팀장이 단일 화면에서 즉시 파악 | 높음 / 미지원 |
| DB-02 | 알림 현황 | 결제 대기·배송 지연·CS 미처리 등 즉각 조치 필요 업무를 알림으로 자동 통지. 누락 업무 방지 및 대응 속도 향상 | 권장 / 미지원 |
| DB-03 | 보고서 연동 및 대시보드 | 주간/월간 매출 보고서 업로드 시 자동 시각화. 일간/주간/월간 통계(구독·매출·CS 추이) + 위하고 ERP 표준 양식 지원으로 영업추진팀의 보고서 재작성 부담 제거 | 높음 / 미지원 |

| 구독 데이터 | C/S MSSQL | 구독·수신자·지로 이력 | 약 10~30만 건 (구독 이력 누적) | 기준일 기반 일괄 이관 + 차분 이관 |
| 결제/재무 | C/S MSSQL | 결제·입금·이연수익 | 약 20~50만 건 (연간 결제 기반) | 기준일 기반 일괄 + 차분 이관 |
| 상품/재고 | C/S MSSQL | 도서·가격·재고 | 약 1~3만 건 (출판물+아트상품 카탈로그) | 일괄 이관 |
| CS 이력 | C/S MSSQL | 상담·발송 이력 | 약 10~30만 건 (상담·발송 이력 누적) | 기준일 기반 일괄 + 차분 이관 |
| 홈페이지 주문 | AWS MSSQL | 자사몰 주문·정기구독 | 약 5~15만 건 (자사몰 주문 누적) | 기준일 기반 일괄 + 차분 이관 |
| CMS 콘텐츠 | AWS MSSQL | 월간지 콘텐츠·작가·서지 | 약 1~5만 건 (월간지 33년분) | 일괄 이관 |
| SP/Trigger 로직 | C/S MSSQL | 20 SPs + 14 Functions + 15 Triggers | 49개 객체 | **애플리케이션 코드로 전환** |
| 첨부 파일 | (해당 시) | 상담 첨부, 이미지 등 | 별도 산정 | 별도 스토리지로 이관 |

### 2.4.2. 이관 원칙

- **무손실 원칙**: 모든 운영 데이터를 누락 없이 이관(검증 리포트 제출)
- **검증 원칙**: 건수·합계·샘플 비교를 통한 이관 정합성 검증
- **롤백 원칙**: 이관 실패 시 즉시 원상 복구 가능한 절차 수립
- **일정 원칙**: 영업 영향 최소화를 위해 야간 또는 휴일 cut-over 수행
- **기술 중립 원칙**: 도착지 RDBMS는 현행 엔진 유지 또는 동등 이상 대안 채택, 특정 클라우드 제품 강제 없음

### 2.4.3. 데이터 매핑 (대표)

| AS-IS (원본) | TO-BE (통합 DB) | 변환 규칙 |
|---------------|----------------|----------|
| 고객 마스터 (48 cols) | customers | 고객 식별자 → customer_code 문자열·앞0 패딩, 연락처 정규화, 이름 공백제거 |
| 구독 마스터 (20 cols) | subscriptions | 복합키(고객 + 구독 일련번호) → 단일 PK, 상태코드 표준화 |
| 수신자 정보 (43 cols) | delivery_addresses + order_items | 받는사람 정보 분리: 배송지 + 주문항목 |
| 재무·결제 (22 cols) | payments | 결제 유형별 입금/환불 분리, 나이스페이 코드 매핑 |
| 거래처 마스터 (49 cols) | partners | 거래처 코드 → partner_code |
| 도서 + 도서가격 | products | 도서·가격 통합, 도서 식별자 → product_code |
| 일반재고 + 선물재고 | inventory | 일반재고+선물재고 통합 |
| 상담 이력 | cs_tickets + cs_histories | 상담이력 → 티켓 + 처리이력 분리 |
| 이연수익 3개 영역 | deferred_revenues | 선수수익 3 테이블 통합 |
| 자사몰 상품 + 옵션 | products (병합) | 홈페이지 상품 → C/S 도서와 통합 |
| 자사몰 주문 + 주문항목 | orders + order_items | 홈페이지 주문 이관 |
| 웹 정기구독 | subscriptions (병합) | 웹 정기구독 → C/S 구독 통합 |
| CMS 콘텐츠 + 작가 | cms_contents + cms_writers | CMS 콘텐츠 이관 (33 cols 정리) |

### 2.4.4. 이관 절차 (권고)

1. **이관 설계 및 매핑 정의** — 현행 → 신규 컬럼 매핑서 작성
2. **시범 이관(Trial Migration) 1~2회** — 샘플 이관·검증·수정
3. **본 이관(Cut-over)** — 사전 공지된 무중단 또는 단시간 정지 윈도우 내 수행
4. **이관 후 검증** — 건수·합계·샘플 비교 (정합성 100% 목표)
5. **안정화 기간(Hyper-care) 운영** — 병행 운영, 모니터링

### 2.4.5. 검증 방안

| 검증 유형 | 방법 |
|---------|------|
| 건수 검증 | AS-IS / TO-BE 영역별 COUNT 비교, 차이 0 허용(중복 통합 시 별도 기록) |
| 정합성 검증 | 합계 비교 — 결제 금액·매출 합계 등 연도별 합계 일치 확인 |
| 샘플 검증 | 무작위 샘플 100건 추출, 원본-대상 1:1 대조, 불일치 항목 분석 |

### 2.4.6. 전환 시나리오 및 롤백

- **권장 시나리오**: **단계적 전환** (병행 운영 → 점진 전환). 빅뱅 전환 대비 리스크 분산·롤백 가능
- **롤백 트리거**: 데이터 정합성 90% 미만 / 주요 기능 오류 / 성능 기준 미달
- **롤백 절차**: ① 신규 시스템 접근 차단 → ② 기존 시스템 재활성화 → ③ 변경 데이터 역이관(Delta) → ④ 원인 분석·재이관 계획

### 2.4.7. 일정 계획 (권고)

| 단계 | 기간 | 활동 |
|:---:|:---:|------|
| 준비 | 1주 | 매핑 테이블, ETL 개발 |
| 테스트 | 1주 | 샘플 이관·검증·수정 |
| 본 이관 | 1일 | 전체 데이터 이관 |

## 2.5. 연동 요구사항

본 사업에서 구축할 신규 시스템과 외부/내부 시스템 간의 연동 요구사항은 다음과 같음.

| 연동 대상 | 연동 방식 | 주요 연동 데이터 | 연동 빈도 / 비고 |
|----------|----------|----------------|----------------|
| 자사몰 (홈페이지) | API | 회원, 주문, 결제, 정기구독 | 실시간. 현재 수동 재입력 → API 자동화 |
| 외부몰 (네이버/쿠팡 등) — Playauto 경유 | API + 어댑터 패턴 | 주문, 배송 | 10분 간격 폴링 (P-1, I-1) |
| CMS (좋은생각 CMS) | API | 회원 권한 부여·회수 (구독↔콘텐츠 권한) | 실시간 자동화 (현재 수동 — 핵심 병목) |
| ERP — 위하고(WEHAGO) | **API 직접 연동** (불가 시 표준 템플릿 기반 Excel 양방향) | 매출 전표, 세금계산서, 거래처, 재고수불부 | 실시간 또는 일 단위. 현재 엑셀 양방향 수작업 |
| PG — 나이스페이 | API (4~5개 계정 통합) | 신용카드/가상계좌/현금영수증 승인·취소·환불 | 실시간 (FN-06 단일 인터페이스 자동 라우팅) |
| 나이스페이 CTI | 웹 기반(SIP/WebRTC) 또는 기존 CTI 복구 | ARS 녹취, 인입 콜 고객 팝업 | 실시간. **현재 KT→LG 전환으로 미작동 — 복구 필요** (CS-03) |
| 금융결제원 | 파일 업로드(`ocrser.txt`) 자동 파싱 + 매칭 | 지로 입금 내역 | 일 1회 (FN-02 자동 매칭) |
| 택배사 (CJ대한통운/우체국) | API | 송장 등록, 배송 추적 상태 | 실시간/주기 동기화 (DL-03, DL-05, I-4) |
| 외부 콜센터 (더아이앤오) | 웹 접근(VPN + MFA) | 인바운드/아웃바운드 상담 데이터, 실적 | 실시간 (CS-05 권한 분리 + SC-06) |
| SMS·알림톡·웹팩스 | 외부 서비스 API | 알림, 마케팅 메시지, 결제 URL, 영수증 팩스 | 실시간 (CS-04, FN-09, CS-09) |
| 신한 인사이트 뱅크 (통장 입금) | 엑셀 업로드 → 자동 매칭 | 입금 내역 (거래처명·금액 기반 미수금 매칭) | 일 1회 (FN-10) |

### 2.5.1. 연동 시 고려 사항

- **장애 대응**: 외부 채널 API(특히 Playauto)에 대해 **Circuit Breaker 패턴** 적용, 3회 재시도(30초 간격), 실패 시 수동 처리 대기열 등록 + 담당자 알림 1분 이내 (품질 시나리오 A-2)
- **보안**: 모든 외부 연동은 HTTPS + OAuth2 인증 적용 (현행 PPTP VPN 대체)
- **확장성**: 신규 판매 채널(11번가, 카카오커머스 등) 추가 시 어댑터 인터페이스 구현으로 기존 코드 수정 0건(Open/Closed 원칙) — 개발 공수 5일 이내 (품질 시나리오 M-1)
- **데이터 정합성**: 채널 간 중복 주문 방지 100%, 채널간 데이터 형식 통합 100% (I-1)
