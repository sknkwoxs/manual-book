# 2단계: 연결 (Connection)

> **"맥락의 복원"**
> 
> 핵심 과제: 파편화된 문서를 '지식 그래프'로 엮어 입법 과정의 맥락 완성

:::caution[ISP 성공의 핵심 단계]
이 ISP의 성패는 **2단계 '연결'**의 설계 깊이에 달려 있습니다. 많은 공공 프로젝트가 1단계(수집)에만 집중하다가, 정작 3단계(서비스)에서 보여줄 콘텐츠가 빈약하여 실패하곤 합니다.
:::

## As-Is 분석 방법론

### 1. 데이터 사일로(Silo) 분석

**목적**: 시스템 간 데이터 단절 구간 파악

| 분석 대상 | 분석 내용 |
|----------|----------|
| **국회도서관** | 소장 자료 메타데이터, 연계 현황 |
| **예산정책처** | 예산 분석 데이터, 법안 비용 추계 |
| **의안정보시스템** | 법안 진행 정보, 투표 결과 |
| **회의록 시스템** | 본회의/위원회 회의록 |

**분석 항목**:
```
□ 시스템 간 연계 현황 (있음/없음/부분)
□ 데이터 공유 방식 (API, 파일, DB Link)
□ 데이터 불일치 사례
□ 연계 시 기술적 장애 요인
```

### 2. 온톨로지(Ontology) 모델링 워크숍

**목적**: 입법 지식 체계의 개체-관계 정의

| 참여자 | 역할 |
|--------|------|
| **기록 연구사** | 기록물 분류 체계 전문성 |
| **입법 전문가** | 입법 프로세스 도메인 지식 |
| **데이터 아키텍트** | 온톨로지 설계 및 구현 |

**워크숍 산출물**:
- 핵심 개체(Entity) 정의: 의원, 법안, 위원회, 정당, 회의 등
- 관계(Relationship) 정의: 발의, 소속, 상정, 의결 등
- 속성(Attribute) 정의: 각 개체의 필수/선택 속성

### 3. ID 체계 정비 분석

**목적**: 시스템별 상이한 식별 체계 현황 조사

| 대상 | 현황 예시 |
|------|----------|
| 의원 식별 | 시스템마다 다른 의원 코드 사용 |
| 법안 번호 | 의안번호, 대안번호 등 다양한 번호 체계 |
| 회의 식별 | 회의록 번호, 회의 일시 등 |

## To-Be 요구 기능

### 1. 국회 지식 그래프 (Knowledge Graph) 구축

**개념**: 입법 관련 모든 개체와 관계를 저장하는 그래프 데이터베이스

```
                              ┌─────────────┐
                              │    의원     │
                              │   (Member)  │
                              └──────┬──────┘
                                     │
              ┌──────────────────────┼──────────────────────┐
              │                      │                      │
              ▼                      ▼                      ▼
       ┌─────────────┐        ┌─────────────┐        ┌─────────────┐
       │    정당     │        │    법안     │        │   위원회    │
       │   (Party)   │        │   (Bill)    │        │ (Committee) │
       └─────────────┘        └──────┬──────┘        └─────────────┘
                                     │
                    ┌────────────────┼────────────────┐
                    │                │                │
                    ▼                ▼                ▼
             ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
             │    회의     │  │   투표      │  │   문서      │
             │  (Session)  │  │   (Vote)    │  │ (Document)  │
             └─────────────┘  └─────────────┘  └─────────────┘
```

**관계 예시**:
| 관계 | 설명 | 예시 |
|------|------|------|
| `발의` | 의원 → 법안 | 홍길동 의원이 A법안을 발의 |
| `소속` | 의원 → 정당/위원회 | 홍길동 의원이 B당 소속 |
| `상정` | 법안 → 위원회 | A법안이 C위원회에 상정 |
| `심사` | 위원회 → 법안 | C위원회가 A법안을 심사 |
| `의결` | 회의 → 법안 | 본회의에서 A법안을 의결 |

### 2. 이종 데이터 통합 파이프라인 (ETL)

**개념**: 내외부 시스템 데이터를 수집·정제·적재하는 미들웨어

```
┌───────────────────────────────────────────────────────────────────────────┐
│                          ETL 파이프라인 구조                               │
├───────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│  [Extract]           [Transform]              [Load]                      │
│                                                                           │
│  ┌─────────┐        ┌─────────────┐        ┌─────────────┐              │
│  │ 의안DB  │───────►│ 정제/변환   │───────►│ 지식그래프  │              │
│  └─────────┘        │             │        │    DB       │              │
│  ┌─────────┐        │ • 포맷 통일 │        └─────────────┘              │
│  │ 도서관  │───────►│ • ID 매핑   │                                      │
│  │   DB    │        │ • 품질 검증 │        ┌─────────────┐              │
│  └─────────┘        │ • 관계 추출 │───────►│  검색엔진   │              │
│  ┌─────────┐        │             │        │  (Index)    │              │
│  │ 외부API │───────►│             │        └─────────────┘              │
│  └─────────┘        └─────────────┘                                      │
│                                                                           │
│  ────────────────────────────────────────────────────────────────────    │
│  실시간 스트리밍 (Kafka/Flink) + 배치 처리 (Airflow)                      │
│                                                                           │
└───────────────────────────────────────────────────────────────────────────┘
```

### 3. 통합 식별 체계 (Master Data Management)

**개념**: 전 시스템에서 통용되는 고유 식별자 체계

| 개체 | 통합 ID 형식 | 예시 |
|------|-------------|------|
| 의원 | `MEM-{대수}-{일련번호}` | MEM-21-0001 |
| 법안 | `BILL-{대수}-{의안번호}` | BILL-21-2100001 |
| 위원회 | `COM-{코드}` | COM-LEGIS |
| 회의 | `SES-{대수}-{회차}-{차수}` | SES-21-390-01 |
