# 국회기록원 디지털 아카이브 구축 ISP

본 문서는 **수집(Collection) → 연결(Connection) → 서비스(Service) → 확장(Expansion)**의 4단계 프레임워크를 기반으로, ISP 사업 수행 시 필요한 **현황 분석(As-Is)**, **목표 모델(To-Be)**, **산출물(Deliverables)**을 정의합니다.

---

## 프로젝트 개요

### 비전

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│              "입법 기록의 디지털 전환과 국민 서비스 혁신"                      │
│                                                                             │
│   잠든 기록 깨우기 → 맥락의 복원 → 쉬운 입법 탐험 → 열린 플랫폼              │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4단계 프레임워크

```
┌───────────────┐    ┌───────────────┐    ┌───────────────┐    ┌───────────────┐
│   1단계       │    │   2단계       │    │   3단계       │    │   4단계       │
│   수집        │───►│   연결        │───►│   서비스      │───►│   확장        │
│  Collection   │    │  Connection   │    │   Service     │    │  Expansion    │
├───────────────┤    ├───────────────┤    ├───────────────┤    ├───────────────┤
│ 잠든 기록     │    │ 맥락의 복원   │    │ 쉬운 입법     │    │ 열린 플랫폼   │
│ 깨우기        │    │               │    │ 탐험          │    │               │
├───────────────┤    ├───────────────┤    ├───────────────┤    ├───────────────┤
│• 자동 수집    │    │• 지식 그래프  │    │• 타임라인     │    │• Open API     │
│• AI 태깅      │    │• ETL 파이프   │    │  시각화       │    │• 리빙 아카이브│
│• 멀티미디어   │    │• MDM 체계     │    │• AI 서비스    │    │• 외부 연계    │
└───────────────┘    └───────────────┘    └───────────────┘    └───────────────┘
```

## 단계별 개요

### [1단계: 수집 (Collection)](./01-collection/) - "잠든 기록 깨우기"

**핵심 과제**: 의원실의 업무 부하 없는 자동화된 수집 체계 및 비정형 데이터 자산화

| 분석 | 목표 기능 |
|------|----------|
| 의원실 업무 프로세스 추적 조사 | Zero-Effort 자동 수집 에이전트 |
| 레거시 데이터 프로파일링 | 지능형 분류 및 AI 태깅 |
| | 멀티미디어 수집 파이프라인 |

### [2단계: 연결 (Connection)](./02-connection/) - "맥락의 복원"

**핵심 과제**: 파편화된 문서를 '지식 그래프'로 엮어 입법 과정의 맥락 완성

| 분석 | 목표 기능 |
|------|----------|
| 데이터 사일로(Silo) 분석 | 국회 지식 그래프 구축 |
| 온톨로지 모델링 워크숍 | 이종 데이터 통합 파이프라인 (ETL) |
| ID 체계 정비 분석 | 통합 식별 체계 (MDM) |

### [3단계: 서비스 (Service)](./03-service/) - "쉬운 입법 탐험"

**핵심 과제**: 국민 눈높이에 맞춘 타임라인 시각화 및 AI 기반 큐레이션

| 분석 | 목표 기능 |
|------|----------|
| 사용자 경험(UX) 분석 | 입법 타임라인 시각화 뷰어 |
| 대국민 서비스 로그 분석 | 생성형 AI (LLM) 기반 서비스 |
| 해외 선진 사례 벤치마킹 | 개인화 대시보드 (My Archive) |

### [4단계: 확장 (Expansion)](./04-expansion/) - "열린 플랫폼"

**핵심 과제**: Open API 생태계 조성 및 국민 참여형 리빙 아카이브 구축

| 분석 | 목표 기능 |
|------|----------|
| 데이터 수요 조사 | Open API 개발자 포털 |
| 법/제도 및 저작권 분석 | 리빙 아카이브 모듈 |
| 기술 트렌드 분석 | 외부 플랫폼 연계 인터페이스 |

## 전략적 제언

:::caution[ISP 성공의 핵심]
이 ISP의 성패는 **2단계 '연결'**의 설계 깊이에 달려 있습니다.

많은 공공 프로젝트가 1단계(수집)에만 집중하다가, 정작 3단계(서비스)에서 보여줄 콘텐츠가 빈약하여 실패하곤 합니다.
:::

**As-Is 분석 시 주의점**:
- 단순 현황 나열이 아닌, **데이터 연결 관점**에서 분석
- 온톨로지 설계를 위한 도메인 전문가 참여 필수

**To-Be 설계 시 주의점**:
- 지식 그래프 설계의 충분한 검토
- 서비스 시나리오와 연계된 데이터 모델 수립

## ISP 최종 산출물

### [산출물 목록](./deliverables/)

#### 1. 현황 분석서 (As-Is Report)
- 정보화 환경 분석서
- 업무 현황 및 데이터 흐름 분석서
- 국내외 선진사례 벤치마킹 보고서
- 관련 법제도 및 표준화 분석서

#### 2. 목표 모델 설계서 (To-Be Design)
- **[아키텍처]** 하드웨어/소프트웨어/네트워크/보안 구성도
- **[데이터]** ERD, 데이터 표준 정의서, 데이터 이관 및 정제 계획서
- **[응용/서비스]** 기능 구조도, 화면 설계서(UI/UX), 인터페이스 정의서

#### 3. 이행 계획서 (Implementation Plan)
- 중장기 발전 로드맵
- 단계별 소요 예산 산출 내역서
- **차세대 구축 사업 제안요청서 (RFP)**
