## As-Is 분석 방법론

### 1. 데이터 수요 조사 (Demand Survey)

**목적**: Open API 활용 수요 파악

| 대상 | 조사 내용 |
|------|----------|
| **시빅해커** | 필요 데이터 종류, 원하는 API 형태 |
| **리걸테크 기업** | 활용 서비스 계획, 데이터 포맷 요구 |
| **학계/연구기관** | 연구용 데이터 수요, 대량 다운로드 필요성 |
| **언론사** | 팩트체크용 데이터, 실시간 알림 필요성 |

**조사 항목**:
```
□ 필요 데이터 항목 (우선순위)
□ 원하는 API 형식 (REST, GraphQL 등)
□ 데이터 갱신 주기 (실시간, 일배치 등)
□ 호출량 예상 (일일 API 콜 수)
□ 인증 방식 선호도
```

### 2. 법/제도 및 저작권 분석

**목적**: 데이터 개방의 법적 근거 및 제약 사항 파악

| 분석 항목 | 내용 |
|----------|------|
| **공공데이터법** | 개방 의무 데이터 범위, 제외 사유 |
| **국회기록물관리법** | 기록물 공개 기준, 비공개 대상 |
| **저작권법** | 기증 기록물 저작권, 이용 허락 범위 |
| **개인정보보호법** | 의원 개인정보, 익명화 기준 |

### 3. 기술 트렌드 분석

**목적**: 최신 Open API 및 연계 기술 검토

| 기술 영역 | 검토 내용 |
|----------|----------|
| **API 표준** | REST, GraphQL, gRPC 비교 |
| **인증/보안** | OAuth 2.0, API Key, JWT |
| **문서화** | Swagger/OpenAPI, API Blueprint |
| **모니터링** | API Gateway, 사용량 분석 |

## To-Be 요구 기능

### 1. Open API 개발자 포털

**개념**: 외부 개발자를 위한 API 허브

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Open API 개발자 포털                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐ │
│  │  API 문서 (Swagger UI)                                                │ │
│  │  ─────────────────────────────────────────────────────────────────── │ │
│  │  GET  /api/v1/members           의원 목록 조회                        │ │
│  │  GET  /api/v1/members/{id}      의원 상세 조회                        │ │
│  │  GET  /api/v1/bills             법안 목록 조회                        │ │
│  │  GET  /api/v1/bills/{id}        법안 상세 조회                        │ │
│  │  GET  /api/v1/bills/{id}/timeline  법안 타임라인 조회                 │ │
│  │  GET  /api/v1/votes             투표 기록 조회                        │ │
│  │  POST /api/v1/search            통합 검색                             │ │
│  └───────────────────────────────────────────────────────────────────────┘ │
│                                                                             │
│  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐            │
│  │  API Key 발급   │  │  사용량 대시보드 │  │  샘플 코드     │            │
│  │  및 관리        │  │  (Quota/통계)   │  │  (Python/JS)   │            │
│  └─────────────────┘  └─────────────────┘  └─────────────────┘            │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**핵심 기능**:
| 기능 | 설명 |
|------|------|
| API 문서 자동화 | Swagger/OpenAPI 기반 인터랙티브 문서 |
| API Key 발급 | 회원가입 후 즉시 발급 |
| 사용량 모니터링 | 일일/월간 호출 횟수, Quota 관리 |
| 샘플 코드 | Python, JavaScript, Java 등 예제 제공 |
| Sandbox 환경 | 테스트용 API 환경 제공 |

### 2. 리빙 아카이브 (Living Archive) 모듈

**개념**: 시민 참여형 수집 및 소통 공간

| 기능 | 설명 |
|------|------|
| **댓글/토론** | 법안별 시민 의견 수렴 공간 |
| **기록물 기증** | 시민 보유 의정 활동 자료 기증 |
| **크라우드소싱** | 자료 정리, 오류 신고 등 참여 |
| **소셜 연동** | SNS 반응 수집 및 표시 |
